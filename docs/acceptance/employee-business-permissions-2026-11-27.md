# ERP员工选品权限维护（2026-11-27）

## 正式维护入口

ERP 8081 → HR Setup → 员工 → 对应员工 → 概况 → 公司信息 → **AIONE业务角色配置**。
技术字段：`Employee.custom_miwa_aione_role_profile`；复用原生 `Role Profile`、`Has Role`、`Role`。
只有ERP System Manager可修改该字段，权限级别9；员工不必建立ERP User。

- `AIONE-普通选品员工`：选品研究、选品收集。允许授权范围内的公共选品池和本人负责记录；无分配、管理全部或授权管理。
- `AIONE-无选品权限`：撤销全部选品业务权限，保留人员和历史业务记录。
- `AIONE-选品管理员`：研究、收集、分配、管理全部、授权管理。仅经业务授权后配置。
- 特殊组合由系统管理员在ERP原生“角色配置”页面维护上述AIONE角色，不通过职位名称推断权限。

保存员工或修改所引用角色配置后，现有ERP主动出站同步传送权限。AIONE不单独维护第二套角色标准。
同步周期目前约60秒；以AIONE接收时间为准，离线期间不应声称撤销已经生效。

## 新增与变更

1. 建立真实Employee，核对唯一美和会员号、在职状态。
2. 登录邮箱使用现有HRMS公司邮箱／个人邮箱字段；缺失资料由管理员补充，不猜测。
3. 选择适当AIONE业务角色配置并保存。
4. 等待人员同步后，员工刷新商品之家；登录授权与选品业务授权是两个独立检查。
5. 货号前缀缺失不影响选品权限，但正式货号申请仍须配置前缀。

本次权限发布不替换既有Google登录认证。全新员工的自动Google身份注册属于先前登录修复工作，其完成状态必须另外验收，不能仅凭角色配置已保存认定新员工可登录。

## 撤销

仅撤销选品：改为`AIONE-无选品权限`并保存，等待同步，验证商品之家拒绝访问。
停用员工：按HRMS现有状态改为非Active，保留历史记录；选品后台检查会拒绝后续操作。
Google登录全局会话撤销属于登录机制验收，不将选品接口拒绝冒充整站退出。

## 兼容与隔离

首次启用同步时，未设置角色配置的历史员工保留原有选品授权，避免意外改变86000。
员工一旦由ERP角色配置接管，后续清空该字段也会撤销，不恢复旧授权。
权限快照带`permissionsSchemaVersion:1`；接管后拒绝退回旧权限快照。
AIONE旧“负责人授权”写入接口在ERP接管后拒绝写入，提示管理员前往ERP维护。
