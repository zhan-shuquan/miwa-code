## 2. 业务参数与计算规则

两边现有汇率均25，平台费率10%、关税10%、目标毛利率40%、价格步长100、尾数80；17条包装/配送费相同。开发多出4种海运方式，仍属未确认试算值，不能随迁移自动成为正式标准。

成本Server Script `AIONE-统一成本定价-TEST` 的哈希不同。定点diff显示开发增加“仅两种现有直发物流包含日本配送”的判断、直发包装置为“-”、切回备货时恢复包装默认值；并调整缺失配送档位校验。不能在HRMS安装时顺带覆盖成本脚本，也不能宣称两边公式完全一致。迁移清单应独立列出这段已有差异，执行前用相同输入回归核对；不另造公式。

唯一管理入口是ERP「设置 → 美和业务参数」。其当前实现是实时引用既有AIONE Cost Settings和Currency Exchange，并保存尚未生效的规则草案。正式8080应迁移此统一入口及引用能力，保留8080原有效值；负责人通过入口核对、修改有效参数。草案值不进入计算，代码审核不等于参数业务批准。

## 3. 迁移包分层

### A. HRMS与必要平台能力

锁定官方HRMS `v16.52.0`，commit `5c72c067c0a3bcc969a49c708b7bec545a046fe9`，源码归档SHA256 `bd8e5e9ad1df01b1567152a7747bb565e7bb1d02e31e177fec0786e6d6a7e286`。复用ERP仓库 `docker/hrms-v16/version-lock.json` 和已验证构建流程，不升级Frappe/ERPNext。

现有HRMS镜像基于8080现有镜像构建，可作为候选基础，但8081还使用大量仓库/运行目录bind mount；仅替换镜像无法迁移这些功能。正式发布镜像应在保留8080基础的前提下，纳入审核通过的文件清单和原生HRMS资源，不引用开发工作目录或未提交文件。保留旧镜像digest。

### B. 员工主数据及编号

必要代码/迁移：`employee_master.py`、`selection_numbering.py`、`selection_numbering_schema.py`、经过筛选的Employee事件hook及版本化安装入口。不得直接整体替换hooks.py，避免引入未批准的定时扫描、通知、美工和发布事件。

复用技术字段：`Employee.custom_miwa_member_id`、`Employee.custom_miwa_item_prefix`、`Item.custom_miwa_selection_id`，不重建第二套人员表。会员号和前缀唯一约束、权限级9与现有权限冲突预检、停用校验、白名单数据投影一起迁移。

5名员工候选会员号：86000、86001、86002、86004、86005。当前前缀分别为zsq、zjl、空、空、空。来源员工ID为HR-EMP-00001、00004～00007。迁移以会员号为幂等键，生成并保留源ID→正式ID映射；不以姓名匹配，不要求员工另建ERP登录。

8080缺少中国公司“武夷山美和跨境电子商务有限公司”，需要先核对并创建其原生Company依赖，再导入对应4名员工。公司默认币种CNY，既有日本公司JPY。公司创建可能触发ERP原生账户/成本中心初始化，应单列审核；不得复制开发账务余额或虚构财务数据。

仅迁移员工原有真实字段、有效引用和必要头像，缺失非核心资料留空。若原生必填校验失败，报告具体行/字段，不填虚假生日、性别、入职日期。职位与人员类型不自动赋予管理权限。

### C. 正式商品与业务历史

- 8080既有129条Item、采购单1、库存凭证2及其依赖全部保留；不覆盖数据库，不删除8080独有商品。
- 95条开发独有商品只列为候选，不自动认定真实。按原商品资料、平台商品关联、成功发布记录及业务负责人确认，形成逐条allowlist。变体必须携带父商品、属性值、UOM、分类品牌、有效价格及必要附件依赖。
- 121条同名商品逐字段dry-run；默认8080为主，只补充批准字段。存在真实平台发布结果的开发记录需要合并关联与幂等证据，不能重新发布来验证迁移。
- 开发平台商品多28、SKU多65、文件多332；数量差不是迁移清单。按已确认商品及店铺链接逐条迁移，先核实external ID与唯一键，保留已有远端ID，禁止重建远端商品。
- 不迁移可执行任务状态、Redis队列、待重试发布、美工任务或收费请求。必要历史成果/日志以不可执行审计记录保留，原始备份保留。
- 567条来源索引、跨店规则、通知/操作任务不整表搬迁，依赖确认商品按需迁移或在批准后重建只读索引。

### D. 货号历史与正式流水

实测纯主货号最大值：8080 zsq020 / zjl275；8081 zsq106 / zjl281。不能直接在8080从当前最大值分配，必须先合并所有已确认真实商品及平台已用货号的历史。

正式编号继续ERP事务锁+唯一约束+幂等selection_id，原生手工建档也遵守预留保护。负责人变更不重编号，重试返回原编号；迁移产生的来源ID映射应纳入幂等键，防止开发与正式selection_id意外碰撞。迁移前导出高水位与预留快照，编号写入开放后禁止倒退流水。

### E. AIONE及连接隔离

正式AIONE→正式Cloud Run/Cloud SQL→正式专用连接器→8080/frontend；开发5500→开发库→开发专用连接器→8081/miwa-dev.localhost。

现有连接器内部硬绑定开发容器和站点。必须先配置化并验证明确的环境目标、站点、数据库/队列、独立secret与来源标识；不能只把AIONE URL改为线上就复用开发连接器。启动时核对实际容器标签/站点，目标不匹配即拒绝。

采用公司主机主动出站HTTPS，保留现有WIF/IAM云桥；不把8080、数据库或Redis公开到互联网，不共享两环境令牌，不放宽Google授权或Cloud Run权限。人员同步仅投影必要字段；员工权限来自正式会员认证和授权配置。

ERP离线：授权缓存只读展示并标记时间；草稿与试算可继续，正式编号/建档待恢复，以租约和幂等收据执行。没有结果确认时不得当作成功或盲目重放。

云端20MB图片传输、私有成本规则服务、正式同步secret配置及真实员工多账号隔离仍是发布前待完成的技术验收；本轮不把5500验收等同于生产联调。

## 4. 防止自动化误执行

8080目前有运行中的scheduler/worker，88类任务未停止，默认没有开发环境的mute_emails保护；本轮没有改变它们。正式实施窗口必须先保存状态，再暂停相关消费者、调度和触发入口，配置生图/发布/邮件禁止执行的明确保护后，才运行迁移与安装hooks。

8081的27项history-hold只留开发环境，不清空、不迁移、不消费。不能通过整体复制common_site_config、sites目录、Redis卷或Docker网络来迁移安全配置。

普通维护/导入与付费生图/发布消费者分离。迁移完成后只恢复批准的维护服务；业务自动化另行明确启用，不能因容器restart自动放行。

1. 负责人确认本方案、员工候选清单、商品allowlist及必要同名更新清单；确定短维护窗口。

4. 在8080基础上安装锁定HRMS并验证原生Employee功能；复核核心版本未变化及既有商品/凭证数量。
5. 按依赖清单迁移必要自定义字段、权限、员工接口、编号能力和统一参数入口；迁移公司及5名获准员工；逐项校验唯一性与来源映射。

7. 配置正式专用连接器与AIONE候选；先完成只读同步和认证检查，再开启草稿操作，最后单独验收正式编号与建档。测试商品仍隔离；正式验收需选择获准真实业务对象。
