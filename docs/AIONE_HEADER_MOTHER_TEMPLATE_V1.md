# AIONE Header Mother Template V1

Status: 正式锁定（平台级母版原则）

## 1. 定位

Header 是美和AIONE一体化工作平台的“头部大脑”。

它负责承载跨工作台、跨业务区域的高频全局能力，并保持清晰、稳定、可扩展的导航逻辑。

## 2. 第一行：平台级母版，正式锁定

第一行承担 AIONE 的全局高频导航，是最核心、最稳定、最具美和特色的导航层。

第一行应体现清晰的业务与认知逻辑，不作为普通快捷栏处理，也不得因单一页面或单一工作台需求随意改动。

原则：
- 平台级全局能力优先
- 导航顺序有明确逻辑
- 高频入口保持稳定
- 允许后续小范围增减，但必须按正式变更流程处理
- 不允许工作台自行改造第一行
- 不允许为了曝光率重复放置完整入口

第一行是 AIONE Header Mother Template 的核心锁定区域。

### AI入口组：AI之家 + 全局AI

AI相关入口在第一行中必须作为一个连续、相邻的逻辑组展示，不得分散到Header两端。

正式定义：
- `AI之家`：进入AI资源、AI岗位/人才、能力、方法、配置与相关管理空间的长期归属入口
- `全局AI（美和AI）`：在任意业务页面随时调用AI进行分析、协助、执行和发起动作的全局工作入口
- 两者职责不同，但属于同一AI认知链，因此必须在Header第一行物理相邻、视觉成组
- 不得因为“AI之家属于核心之家、全局AI属于工具”而把两者拆散
- 后续可以优化图标、间距、分隔符、强调方式，但“并列相邻”属于锁定规则

用户认知应保持简单：

`AI之家｜美和AI`

即：需要进入AI体系时去AI之家；需要立刻让AI工作时直接调用美和AI。

## 3. 快捷能力：取消独立物理第二行

快捷能力仍然保留，但不再占用 Header 的独立物理行。

正式原则：
- 各应用、工具、店铺和第三方系统首先归属到各自真实业务区域
- 正常情况下，用户按常规业务路径打开
- 只有用户自己认定为高频使用的入口，才考虑加入个人快捷
- 快捷属于可选的个人效率能力，不强制、不预设、不替代主导航
- Header 后续如实现快捷，仅使用单个轻量入口（图标或“快捷”文字）按需弹出，用完归位
- 工作之家可作为“我的快捷”的个人管理入口
- 不为了快捷另建一套重复的应用导航体系

因此，原“第二行高频快捷栏”正式取消。

## 4. 美和精神：取消独立物理行

美和精神极其重要，但不再作为 Header 中长期常驻的一整行展示。

正式定位调整为：
- 美和精神首先是开发者、设计者、管理者必须真正理解和贯彻的底层原则
- 用户不需要通过口号栏被动接受，而应在使用系统的过程中，通过流程、规则、交互、信息结构、决策方式和结果逐步理解与感受到美和的方法和价值观
- 美和精神应进入产品原则、业务方法、工作手册、学习内容、知识资产和实际系统行为，而不是依赖 Header 常驻文案表达
- 未来如出现更自然、更有价值的表达方式，可以再通过电子出版物、工作手册、学习手册、情境提示等载体呈现

因此，原“第三行美和精神层”正式取消，不再占用 Header 固定高度。

核心原则：

> 美和精神最重要的不是被看见，而是被系统真正贯彻；不是靠口号告诉用户，而是在使用过程中让用户逐步领悟并找到答案。

## 5. 唯一脖子：今日印象 / 重要日程 / 重要通知

在第一行平台大脑之下，Header 只保留一条长期稳定的轻量信息带，作为 AIONE 唯一的“脖子”。

该信息带固定三项内容：
- 今日印象
- 重要日程
- 重要通知

以上顺序沿用既有 Header 基线，不重新发明。

### 今日印象既有定义

“今日印象”从既有开发基线继续继承，不作为新功能重新定义。当前正式内容体系包括：
- 当前地点 / 工作地点
- 公历日期
- 星期
- 当地时间
- 农历
- 节气
- 星座
- 当地当前天气状态
- 当前温度
- 体感温度

其中节气与星座继续属于“今日印象”的内容体系，但不再作为 Header 常驻直接显示字段；可在展开、Popover、详情或后续更合适的呈现方式中出现。

历史 V1.9.1 已明确锁定：日期、星期、时间、农历继续保留；节气与星座不再占用 Header 常驻直接展示空间。当前代码已经具备按用户地点和时区展示天气、实时温度与体感温度的能力。因此，天气与温度属于“今日印象”内部内容，不拆成第四个独立模块。

### 重要日程

负责当天及近期真正关键的时间安排。保持轻量，只突出需要用户感知的重要日程，不把完整日历或一般待办堆入 Header。

### 重要通知

负责真正需要用户注意的重要消息。保持轻量，不把全部通知流复制到 Header。

### 唯一脖子原则

- 这是 Header 唯一保留的第二层物理区域
- 必须长期存在
- 三项职责一个不少
- 视觉必须轻、薄、低干扰
- 允许采用图标、短文本、角标、Popover 等方式进一步压缩高度
- 可以优化呈现方式，但不得随意重新定义既有内容
- 不将一般待办、复杂业务操作或低优先级消息塞入该信息带

其目标是在极低高度内，让用户快速获得“此刻与今天最值得知道的信息”。

## 6. Header 物理结构原则

当前正式结构：

第一行 = 平台大脑 / 核心全局导航（固定、锁定；AI之家与美和AI必须相邻成组）
第二行 = 唯一脖子 / 今日印象 + 重要日程 + 重要通知（固定职责、轻量呈现）
快捷 = 逻辑能力，不占独立物理行
美和精神 = 产品与方法原则，不占独立物理行

核心原则：

> 大脑稳定，脖子轻薄；其他能力按需出现。Header 保持完整认知，但不以堆叠高度换取功能完整。

## 7. 变更规则

第一行属于正式母版锁定范围，修改必须记录：
- 原内容
- 新内容
- 修改原因
- 影响范围
- 生效状态

`AI之家 + 美和AI` 的并列相邻关系属于第一行正式锁定规则。后续不得在没有正式变更记录的情况下再次拆开。

唯一脖子的三项职责也属于锁定范围。今日印象必须继承既有开发定义；如未来需要增删其内容，应先核对历史基线与现有实现，再走正式变更流程，不得在新讨论中重新解释旧功能。

快捷、美和精神等能力的呈现方式可以继续优化，但不得破坏第一行的平台大脑职责，也不得重新把大量低频内容堆回 Header。

## 8. 开发要求

后续 Header 代码应尽量形成统一平台级组件：

`PlatformHeader`

各工作台和事业复用同一 Header 母版，不允许复制出多个独立 Header 实现。

建议将唯一脖子独立为可复用子组件，例如：

`HeaderDailyContextBar`

该组件统一处理今日印象、重要日程和重要通知；其中今日印象继承地点、公历日期、星期、当地时间、农历、节气、星座、天气、温度和体感温度等既有内容，并允许根据当前用户地点及时区动态更新。

业务页面仅通过配置决定需要展示的上下文内容，不直接修改 Header 核心结构。
