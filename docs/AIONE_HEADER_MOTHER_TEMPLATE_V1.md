# AIONE Header Mother Template V1

Status: 正式锁定（平台级母版原则）

## 1. 定位

Header 是美和AIONE一体化工作平台的“头部大脑”。

它负责承载跨工作台、跨业务区域的高频全局能力，并保持清晰、稳定、可扩展的导航逻辑。

## 2. 第一行：平台级母版，正式锁定

第一行承担 AIONE 的全局高频导航，是最核心、最稳定、最具美和特色的导航层。

第一行应体现清晰的业务与认知逻辑，不作为普通快捷栏处理，也不得因单一页面或单一工作台需求随意改动。

原则：
- 平台级全局能力优先
- 导航顺序有明确逻辑
- 高频入口保持稳定
- 允许后续小范围增减，但必须按正式变更流程处理
- 不允许工作台自行改造第一行
- 不允许为了曝光率重复放置完整入口

第一行是 AIONE Header Mother Template 的核心锁定区域。

## 3. 快捷能力：取消独立物理第二行

快捷能力仍然保留，但不再占用 Header 的独立物理行。

正式原则：
- 各应用、工具、店铺和第三方系统首先归属到各自真实业务区域
- 正常情况下，用户按常规业务路径打开
- 只有用户自己认定为高频使用的入口，才考虑加入个人快捷
- 快捷属于可选的个人效率能力，不强制、不预设、不替代主导航
- Header 后续如实现快捷，仅使用单个轻量入口（图标或“快捷”文字）按需弹出，用完归位
- 工作之家可作为“我的快捷”的个人管理入口
- 不为了快捷另建一套重复的应用导航体系

因此，原“第二行高频快捷栏”正式取消。

## 4. 美和精神：取消独立物理行

美和精神极其重要，但不再作为 Header 中长期常驻的一整行展示。

正式定位调整为：
- 美和精神首先是开发者、设计者、管理者必须真正理解和贯彻的底层原则
- 用户不需要通过口号栏被动接受，而应在使用系统的过程中，通过流程、规则、交互、信息结构、决策方式和结果逐步理解与感受到美和的方法和价值观
- 美和精神应进入产品原则、业务方法、工作手册、学习内容、知识资产和实际系统行为，而不是依赖 Header 常驻文案表达
- 未来如出现更自然、更有价值的表达方式，可以再通过电子出版物、工作手册、学习手册、情境提示等载体呈现

因此，原“第三行美和精神层”正式取消，不再占用 Header 固定高度。

核心原则：

> 美和精神最重要的不是被看见，而是被系统真正贯彻；不是靠口号告诉用户，而是在使用过程中让用户逐步领悟并找到答案。

## 5. 今日印象 / 重要通知 / 重要日程：继续做轻

今日印象、重要通知、重要日程属于轻量即时信息能力，不作为 Header 核心导航。

原则：
- 做轻
- 低干扰
- 信息密度受控
- 不抢占 Main 的主要工作空间
- 不将大量待办、复杂操作或业务流程堆入 Header
- 后续允许继续寻找更合适的按需呈现方式，例如 Popover、Drawer、Context Strip 或其他轻量交互

该区域的具体物理位置与展现方式暂不硬锁定，以真实使用效果为准持续优化。

## 6. Header 物理结构原则

当前正式方向：

第一行 = 平台大脑 / 核心全局导航（固定、锁定）
快捷 = 逻辑能力，不占独立物理行
美和精神 = 产品与方法原则，不占独立物理行
今日印象 / 重要通知 / 重要日程 = 轻量即时信息能力，展现方式继续优化

核心原则：

> 保留丰富能力，减少长期占用；逻辑可以完整，物理 Header 必须尽量轻。

## 7. 变更规则

第一行属于正式母版锁定范围，修改必须记录：
- 原内容
- 新内容
- 修改原因
- 影响范围
- 生效状态

快捷、美和精神、即时信息等能力的呈现方式可以继续优化，但不得破坏第一行的平台大脑职责，也不得重新把大量低频内容堆回 Header。

## 8. 开发要求

后续 Header 代码应尽量形成统一平台级组件：

`PlatformHeader`

各工作台和事业复用同一 Header 母版，不允许复制出多个独立 Header 实现。

业务页面仅通过配置决定需要展示的上下文内容，不直接修改 Header 核心结构。
