# 选品池 V1.0：产品与技术约定

状态：开发分支验证中，未合并 main、未部署线上。2026-11-26。

## 产品定义

本轮以用户《选品池 V1.0 完整开发指令》及人员前缀补充答复为准。V3.9的“不开发选品池”范围限制由本轮明确授权替代；原成本公式、表单配置和同步业务保持。

商品之家导航：选品池、选品录入、选品一览。选品池的待认领、我的认领、全部选品是同一 product_opportunities 对象的不同权限范围。原始选品人固定，负责人可变，认领/分配时间与操作者独立记录。

加入选品池不要求成本字段。直接录入仍可独立使用。公共机会的参考价格、来源销量、供应商信息属于来源证据，不直接写入已确认采购成本或公司实际销量。

选品号：Asia/Tokyo业务日、统一事务计数器，xp+YYMMDD+至少3位流水，超过999自然扩展。既有编号与正式货号不覆盖。幂等键绑定操作者和内容哈希；原始批量分享文本保存在 intake 请求审计。

正式货号：ERP人员主数据的明确会员号及前缀关联；不推测人员映射。保存草稿、认领不要求前缀。确认资料后持久化编号申请，ERP处理成功才进入confirmed；离线保留number_pending。已有正式货号重复确认返回原值，负责人变更不重编号。

人才之家只增加前缀关联设置入口。管理员可写，普通员工只读。主要负责人的收集、分配、管理及授权管理能力通过 pool-grants 配置，86000仅作为初始授权配置，不用于权限判断分支。

确定性重复阻止新建；SNS相同内容但不同商品文本提示核对，不自动合并。采购URL再次核对全局身份索引及ERP目录。无权限时只返回重复提示。已编号记录归档保留，禁止永久删除；复制相同采购链接或商品原图也受到全局去重限制。

## 技术实现

- 0201_selection_pool.sql：canonical机会新增选品号，复用计数器；新增幂等审计、身份索引、ERP命令outbox，均为支持表，不建立第二套商品/人员主表。
- pool service：编号、来源查重、状态转换、统一 work_items 研究任务。
- pool route：后端权限、批量收集/预检、查询、导出、原子认领及人员设置请求。
- ERP命令：持久化租约、重试、全局事务锁保证编号期间归属/状态一致；ERP内GET_LOCK、native Series和永久Reservation负责正式序列。ERP原生Item新建也在同一事务写入该唯一登记，普通管理界面不可编辑/删除/重命名预留；原生建档没有已确认人员映射时会员号留空，不推测归属。唯一冲突最多重试5次。
- Employee.custom_miwa_member_id / custom_miwa_item_prefix为正式映射；Item.custom_miwa_selection_id用于校验预留来源。安装脚本仅绑定8081开发站点。
- 图片复用原始资产表及preview/thumbnail生成器。公共file-intake统一点击/拖拽/粘贴；多图合并逐张传输，单张仍按统一20MB默认配置。
- 原始1688 XLSX字段实际包含商品主图、主图链接、加入时价格（人民币）、月销量等；保留嵌入图和来源证据。远程图采用HTTPS、DNS固定、公网地址校验、体积/超时/重定向限制。现有1688授权配置可用时复用现有客户端；未授权不模拟读取成功。
- UI复用AIONE Shell、SVG、排序状态组件和工作台样式Token；原动态录入布局保留。
