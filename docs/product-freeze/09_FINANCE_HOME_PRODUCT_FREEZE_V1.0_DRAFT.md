# 09｜财务之家 Product Freeze V1.0 Draft

状态：Draft / 待冻结
适用：美和AIONE一体化工作平台（AIONE）

## 1. 定位
财务之家是AIONE统一的财务事实与财务处理域，负责承载收入、支出、应收、应付、资金、成本、会计、税务、预算和报表等企业财务事实与管理视图。

财务之家不是各业务页面重复录入金额的第二套系统。业务事实应优先从订单、采购、渠道、往来、工作等权威对象自动流入，财务域负责财务确认、归类、核算、结算、对账、预算和报表。

## 3. 核心业务对象
- FinancialAccount：财务账户/科目相关基础对象
- RevenueRecord：收入事实
- ExpenseRecord：支出事实
- ReceivableRecord：应收事实
- PayableRecord：应付事实
- CashTransaction：资金流水
- CostRecord / CostAllocation：成本与分摊记录
- AccountingEntry：会计分录
- TaxRecord：税务记录
- Budget / BudgetLine：预算及预算明细
- FinancialStatement：财务报表快照或正式报表引用

具体对象边界在横向Review和Technical Design阶段继续收口，避免与外部会计系统重复建模。

## 4. 唯一事实源
财务确认后的金额、结算状态、应收应付、资金流水、成本归集、会计处理、税务事实、预算与正式报表由财务之家维护。

不重复维护：
- 商品/SKU事实 → 商品之家
- 客户/供应商主体 → 往来之家
- 渠道主体 → 渠道之家
- 工作执行事实 → 工作之家
- 业务经营分析 → 分析之家

财务通过Reference引用来源对象，并保留source_object_type / source_object_id。

## 5. 业务事实进入财务的原则
业务系统负责产生真实业务事实，财务系统负责确认财务含义。

例如：
- 销售订单产生收入候选事实
- 采购/物流产生支出或应付候选事实
- 退款/售后产生冲销或调整候选事实
- 工资/服务费产生应付或费用事实

不得要求员工在业务系统和财务系统重复录入同一笔事实。

## 6. 基础数据中心
负责公司、币种、税率、科目、结算方式、付款方式、银行账户、支付账户、成本中心、预算维度等财务基础配置。

基础数据必须有统一编码和版本，不允许各页面自行定义第二套币种、税率或科目名称。

## 7. 收入 / 支出
收入与支出中心管理已经具有财务意义的业务事实。

至少保留：来源对象、金额、币种、税额、含税/未税、确认日期、事业、渠道、往来方、负责人/确认人、状态、凭证引用、备注、版本。

## 8. 应收 / 应付
Receivable / Payable表达“应该收/应该付”以及实际结算过程。

不得用订单状态直接替代财务结算状态。

建议字段：counterparty_ref、source_ref、amount、currency、due_date、settled_amount、remaining_amount、status、settlement_refs、aging_bucket。

## 9. 资金中心
资金中心管理银行、支付平台、现金等真实资金流水及账户余额视图。

资金流水与收入/支出/应收/应付是不同层次，不得用一张表混在一起。

需要支持对账、匹配、未匹配项、差异、余额校验。

## 10. 成本中心
成本中心负责商品成本、物流成本、渠道费用、广告费用、人工/服务成本、项目成本等财务成本归集与分摊。

商品之家可以展示成本引用或运营成本视图，但财务确认后的正式成本口径由财务之家统一。

成本分摊规则必须可追踪、可版本化，不得写死在页面。

## 11. 会计中心
会计中心负责分录、凭证、期间、结账、调整等正式会计处理。

AIONE不应低质量复制成熟会计软件；如外部会计系统是正式账务事实源，AIONE通过Integration引用和同步，重点提供统一业务上下文、映射和管理视图。

## 12. 税务中心
税务中心承载税率规则引用、税务期间、申报资料、纳税记录、税务调整、相关凭证与外部税务系统引用。

税务规则属于高风险专业规则，不让AI自由判断替代正式规则或专业人员确认。

## 13. 预算中心
预算至少支持年度/月度、事业、部门、项目、渠道、科目等维度。

预算与实际发生事实分离，支持预算、实际、差异、预测。

预算调整必须保留版本与审批/确认历史。

## 14. 报表中心
报表中心负责标准财务报表和管理财务报表的统一出口。

正式报表应基于已确认财务事实生成，不复制维护第二套数字。

- 09_00_概览 → PT-01 Overview Page
- 收入/支出/应收/应付/资金/成本列表 → PT-02 Object List Page
- 单笔财务对象 → PT-03 Object Workspace
- 对账/结算/结账等阶段流程 → PT-04 Workflow Page

- 基础数据/税率/科目/预算规则 → PT-06 Configuration Page
- 会计/银行/支付/税务系统连接 → PT-08 Integration Page
- 财务资料管理 → PT-02 Object List + File & Asset

## 16. View / Scope
Scope建议：公司、事业、部门、项目、渠道、往来方、币种、期间、状态、负责人、风险。

View建议：概览｜来源｜结算｜凭证｜对账｜历史｜关联对象。

## 17. 状态
应收应付建议：OPEN、PARTIALLY_SETTLED、SETTLED、OVERDUE、DISPUTED、CANCELLED、ARCHIVED。

收入支出建议：DRAFT、PENDING_CONFIRMATION、CONFIRMED、ADJUSTED、VOIDED、ARCHIVED。

会计期间/结账状态与业务记录状态分离。

## 18. 权限
至少支持Role、Scope、Object、Field、Action Permission。

财务域重点保护：银行账户、支付账号、成本、利润、工资/报酬、税务、预算、会计凭证、机密报表。

高风险动作如付款确认、冲销、调整、关账、税务确认、永久删除必须单独授权并Audit。

## 19. AI与自动化
AI适合：票据/凭证识别、摘要、分类建议、异常提示、对账辅助、预算偏差解释、经营财务分析。

确定性能力优先：金额计算、税率规则、汇率来源、到期日、账龄、余额、预算差异、凭证编号、会计期间、结算状态。

所有AI调用统一经过AIONE AI Gateway，高风险财务结论必须由人确认。

## 20. 财务闭环
真实业务发生 → 财务候选事实 → 财务确认 → 应收/应付 → 资金结算 → 成本/会计/税务处理 → 报表 → 分析与预算 → 管理决策。

## 21. 外部系统与Google生态
支付平台、银行、Robot-in、会计软件、税务系统等优先通过API/Connector/Integration接入。

分析层可进一步使用BigQuery + Looker/Looker Studio，但分析副本不得反向成为交易事实源。

## 22. 资料管理
发票、收据、银行明细、合同、税务资料、申报资料、会计凭证附件、报表文件统一走File & Asset并关联财务对象。

敏感财务资料必须实施严格Scope和Field/File Permission。

## 23. 异常治理
必须处理：重复录入同一业务金额、订单金额与财务确认金额混淆、收入与资金流水混为一体、应收应付与付款状态混淆、成本多套口径、税率硬编码、汇率来源不明、对账差异无处理、跨事业越权、财务数据进入分析副本后反向覆盖主数据。

## 24. 验收标准
1. 业务事实只录入一次，财务通过来源引用和确认形成财务事实。
2. 收入、支出、应收、应付、资金、成本边界清楚。
3. 正式成本口径由财务之家维护，其他域只引用。
4. 会计/税务不低质量重复成熟外部系统能力。
5. 预算与实际分离并支持版本/差异。
6. 财务报表来自统一财务事实，不维护第二套数字。
7. 高风险财务动作有权限、确认和Audit。
8. AI只做辅助识别、分类、解释和异常分析。
9. 文件和敏感字段实施严格权限。
10. 当前文档定义Product/Architecture Truth，不自动声明main已实现。
