# V3.9 收尾优化与验收记录

日期：2026-11-25（日本时间）。分支：`feat/aione-three-homes-discovery`。

状态：实现完成，待业务验收；浏览器本地文件上传验收尚未完成，不标记全部通过。

## 范围与实现

- 同一选品表单增加商品录入／市场调研两个工作区，只切换可见模块，不重新创建记录或表单。保存、确认、返回及右侧核算共用。
- 采购与市场链接复用公共 external SVG；图标提供提示、无有效链接时不能打开。
- 原始选品人复用 `product_opportunities.created_by_person_id`，姓名读取人才之家 canonical `people.display_name`。负责人继续使用 `owner_person_id`；没有新增重复人员字段。
- 库存类型仅取 ERP `AIONE Cost Settings.logistics` 中启用记录的 `method → fulfillment` 关联。无关联、冲突关联均返回待判定。前端联动，后端重新派生，忽略客户端人工库存类型。
- V39 动态布局配置一次性迁移基本信息为 2＋2＋3，底部为简称／库存类型／商品分类／品牌；迁移完成后仍由管理员配置位置及宽度。只去除采购价及国内运费的行内 JPY 展示。
- 简称复用快照内 ERP `miwa_ai.product_names.identify`。人工编辑标识保存在现有选品 JSON 中，自动识别与保存不会覆盖；旧记录已有简称按保守原则保留。自动简称遇到新标题无可靠匹配时清空，不沿用错误旧名称。
- 确认选品预检查与后端确认使用同一 `confirmationIssues`，不要求简称、分类及品牌。缺失必填项显示原因并定位字段。草稿不完整仍可保存；正式 ERP 提交继续执行已有完整性、版本及成本差额校验。
- 列表字段名称和人员显示已统一，所有 20 个可排序业务列由服务端对完整查询结果排序，再分页。公共 `table-sort.js` 处理排序状态、方向切换和图标；数值列以 numeric 排序，日期按时间排序，待计算结果使用 NULL、置于末尾。

没有修改 ERP 成本公式、同步机制、权限规则或数据库业务对象，没有发布商品或调用付费 AI。只重启隔离的 8765 预览进程；ERP 8080、8081 容器及线上 AIONE 未部署变更。

## 尚未解决／待验收

1. 浏览器点击上传、拖拽、Ctrl+V上传仍需补验。当前扩展权限不允许自动选择本地文件；本轮没有改变浏览器安全权限。后台20MB、原图保留、预览缩略图与持久化测试通过，但不能据此宣布浏览器上传全部通过。
2. ERP现有命名规则没有“收纳坐墩”的可靠匹配。按用户要求不扩展命名体系、不调用付费AI，允许人工补充且不会被覆盖。其他已覆盖品类已实测自动识别。

到此停止追加开发范围，保留当前分支供正式业务验收；不合并main、不自动部署线上。
