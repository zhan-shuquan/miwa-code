# ADR｜12之家业务组织层 + 统一 ERP 底座 + 横向 AI 能力

- 日期：2026-10-17
- 决策状态：**业务与架构方向已确认；Repo CURRENT 生效以本 ADR 的 PR 通过并合并 main 为准**
- 项目：美和AIONE一体化工作平台（简称 AIONE）
- ChatGPT 项目空间：02|AIONE系统
- 范围：AIONE 平台级产品、业务对象、通用操作能力与工程治理
- 类型：Architecture Decision Record（ADR）

## 1. 核心决策

**12之家定义美和业务的组织方式、导航入口与职责边界；成熟 ERP 的常规资料管理能力由统一平台底座提供；各之家通过统一业务对象、字段、View/Scope、规则和工作流配置承载差异；AI 作为横向服务嵌入实际业务。**

12之家是 AIONE 的特色，**不是**12套独立 ERP，更不是要求每个之家重复开发一套字段表单、表格、启停、导入导出和权限。

## 2. 职责分层

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 12之家业务组织层 | 导航、业务入口、对象归属、责任与上下文 | 再造通用 CRUD / 导入导出 / 表格引擎 |
| 统一 ERP 底座 | 对象与字段模型、标准页面类型、表格、表单、搜索筛选、排序、批量操作、状态、权限、审计、导入导出、关联、数据 API | 将每个之家的固定业务流程硬编码进通用引擎 |
| 各之家业务配置与领域规则 | 业务对象、字段约束、View/Scope、计算、例外规则、责任人、生命周期、必要业务适配器 | 复制相同字段定义、数据表或已有通用组件 |
| AI 与自动化层 | 基于统一对象与权限执行搜索、摘要、校验、分析、建议与受控操作 | 取代确定性规则或绕过权限、业务确认和审计 |

## 3. 通用 ERP 能力应按“完整操作单元”设计

对一般主数据、资料和台账对象，先评估是否复用现有的标准对象工作区（列表、详情、编辑），并按需启用：

- 新增、编辑、复制、删除或归档（依对象政策和引用保护）
- 启用、停用、默认、排序、状态管理
- 搜索、筛选、视图、字段显隐与顺序
- 单项及批量操作、导入、导出、错误预览
- 统一权限、操作日志、版本与变更追溯
- 关联对象、引用统计、基础报表

**这些是平台通用能力清单，不代表所有对象必须露出所有按钮。** 按对象类型、权限、生命周期和业务场景配置适用功能；危险操作加受控确认。

配置新增字段并不自动改变核算公式、API 合同、平台上架映射或数据库结构。影响核心业务规则仍须采用受控适配器、明确 Contract 和测试。

## 4. 用户体验与审计

- **员工完成业务，系统处理技术。** 日常操作应尽量“编辑 → 保存”，不得要求员工运行 SQL、使用 Cloud Shell 或反复填写系统可推导的信息。
- 自动记录操作者、时间、对象、版本、变更范围及前后差异；不得把审计与普通设置保存时的手写原因强绑定。
- 对确有风险的操作（例如删除被引用资料、正式对外发布、不可逆批量变更），使用必要的确认与审批，不把所有普通操作都设计成高风险流程。
- 新建业务对象或日常启停必须有受控后台入口；SQL 仅用于迁移、修复及正式运维。
- 业务界面简洁、低操作成本；架构约束由 API、数据库和 CI 负责执行。

## 5. 统一对象及状态原则

- 一个业务对象应有唯一主数据与稳定 ID；跨之家使用不同 View/Scope，不复制实体或字段。
- 统一对象身份与展示名称；名称变更不破坏历史引用。
- 店铺业务启用状态与外部平台 API 授权严格分离，启用内部店铺**不等于**准许乐天 RMS 商品发布。
- 已停用对象保留历史数据与关联；对新对象的可选性由正式状态和权限决定。
- 一般实体尽量由共享模板 + 共享组件 + 配置 + 数据生成。只有稳定且确实特殊的业务模式才新增 Page Type。

## 6. 开发与验收方式

1. **先看成熟 ERP 的标准功能，再定义 AIONE 差异。** 产品冻结时一次明确完整基本操作、字段、状态、权限、批量功能、异常及验收条件。
2. 先核对 Repo 已有的对象、组件、页面类型与 Contract，优先复用而非复制。
3. 以业务闭环验收（例如店铺启停 → 商品选择 → 保存读取 → 成本计算），不是仅验收按钮出现。
4. 自动化测试覆盖通用操作、权限、引用、历史兼容、导入导出和回归；用户重点验收真实业务结果。
5. Product Freeze → Technical Design → Branch → CI → Preview → Review → Merge main；main 永远是稳定基线。
6. 不因追求完整而制造无必要字段、流程和页面。复杂留给平台底座，前台操作保持简单。

## 7. 与当前 PR #206 的关系

本 ADR 规定长期方向，**不声称 PR #206 已实现全部通用 ERP 能力**。

PR #206 现阶段主要围绕共享设置、正式店铺主数据、商品字段及配送关联。具体完成程度以其验收报告、代码和 CI 为准。后续店铺管理的真正后台启停入口属于标准 ERP 对象管理能力，不应依赖每次执行 SQL，也不应被包装成每个店铺专用的页面补丁。

## 8. 决策效果及边界

本决策确立：**AIONE 的独特性来自 12之家组织业务、统一对象关系、业务规则与 AI 原生能力，而不是重复建设常规 ERP 操作。**

具体 12之家最终命名、所有模块归属、已实现列表及部署状态，均以 Repo CURRENT 产品定义与真实实现为准，不从本 ADR 反推已完成状态。

后续如果拟新增第二套同类字段引擎、独立表格/表单实现、同一对象的重复数据库实体或按页硬编码配置，应先提出可证明的必要性并经过架构 Review。
