【人工验收顺序】
A. 默认入口
- 点击Header“工作之家”，必须进入今日工作。

B. Sidebar
- 事业工作之后出现团队工作。
- 顺序为：事业工作 → 团队工作 → 等待中 → 异常处理 → 待验收 → 工作记录。

C. 四个核心入口
- 今日工作：今天先做什么。
- 全部工作：查找/比较/筛选全部可见工作。
- 事业工作：按事业进入经营现场。
- 团队工作：看团队成员当前/周期工作分布。

D. 工作手册深链
- 今日工作点击“查看工作手册” → 今日工作章节。
- 全部工作 → 全部工作章节。
- 事业工作 → 事业工作章节。
- 团队工作 → 团队工作章节。
- 等待 / 异常 / 待验收 / 工作记录同样直达对应章节。

E. 团队工作
- 当前 / 本周 / 本月 / 本年可切换。
- 成员卡片/列表可切换。
- 点击成员“查看工作”后进入该成员的统一Work Item Browser。
- 打开具体Work Item后，点赞/关注/处理继续使用既有真实能力。

F. 工作记录
- 只看历史工作事实。
- 不再出现旧“人员工作汇总”主切换。
- 本周 / 本月 / 本年正常。

G. 列表 / 卡片
- 控件顺序为：列表 → 卡片下拉 → 刷新。
- 卡片下拉包含2列 / 3列 / 4列 / 6列。
- 选定一个列数后刷新页面，最近选择保持。
- Main变窄时自动降列，不能出现不可读窄卡。

H. 回归闭环
- 任选一条真实工作执行：打开 → 开始执行 → 添加证据 → 提交完成 → 待验收 → 确认完成。
- 确认V1.9.36点赞/关注、金额/时间条件展示和Header提醒没有回归。

【部署说明】
本版只有前端/路由/出版章节锚点变化，没有Backend或数据库变化。
正常流程：GitHub Desktop提交并Push main → 等待现有前端部署链更新 → 浏览器Ctrl+F5验收。
不要为V1.9.37重新执行Cloud SQL迁移，也无需仅为本版重建Cloud Run Backend镜像。
