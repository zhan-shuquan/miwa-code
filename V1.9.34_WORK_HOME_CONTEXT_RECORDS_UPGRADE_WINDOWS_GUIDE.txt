MIWA AIONE V1.9.34｜工作之家 V2.0 场景减法 + 工作记录升级
Windows Safe 更新与人工验收指南

一、更新方式
1. 停止正在运行的本地 AIONE / Live Server / AI Backend。
2. 解压本次 ZIP，打开其中 code 文件夹。
3. 将 code 文件夹里面的内容合并/覆盖到 D:\miwa\code\ 。
4. 选择替换同名文件；不要先删除 D:\miwa\code，本次仍然是增量覆盖。
5. 本版再次修改了 Backend。覆盖后必须按现有 AIONE Backend 流程重新部署/重启 Backend，再启动页面；只更新前端会导致“关注”继续出现 not_found。
6. GitHub Desktop 检查变更，人工验收通过后 Commit + Push origin。

二、本版不需要数据库迁移
- 关注继续复用既有 work_item_participants 的 observer 角色。
- 工作记录继续读取既有 work_items / work_item_participants 等事实。
- 没有新增第二套任务表、关注表、绩效表或日历任务表。

三、先确认 Backend 真的已经升级
浏览器或现有API验证方式访问：
/api/v1/work-home/capabilities

预期关键内容：
- workHomeVersion = V1.9.34
- companyVisibility = true
- following = true
- participantFacts = true
- employeeWorkSummary = true

如果这里仍404或版本不是V1.9.34，说明实际运行的Backend仍是旧版；此时不要继续判断关注按钮前端是否正常，先完成Backend部署/重启。

四、本版重点人工验收

1. 工作概览 / 《美和工作手册》
- 继续使用统一美和数字出版物母版；
- 前半部分为方法论；
- 后半部分应按Sidebar顺序出现：今日工作、全部工作、我的关注、事业工作、等待与阻塞、待验收、工作记录；
- 应看到简单的STEP操作演示、模拟工作卡和直接进入对应页面的入口；
- 工作记录章节应解释“事实层 ≠ 绩效评分”。

2. 今日工作
- 使用轻量工作事项一览；
- 保留简单搜索、卡片/列表和刷新；
- 不应机械显示全部工作的关系/优先级/事业/团队/项目全套控制项。

3. 我的关注
- 与今日工作使用同一工作事项一览结构；
- 只显示已关注内容；
- 页面不要出现无意义的一堆KPI和全套筛选；
- 关注不等于接手、不进入自己的执行权限。

4. 关注真实闭环（必须真实验收）
- 进入“全部工作”；
- 找到一项可见但不是自己负责的工作，点击“☆ 关注”；
- 页面刷新后仍应显示“★ 已关注”；
- 进入“我的关注”应能看到该事项；
- 点击取消关注并刷新后，该事项应从“我的关注”消失；
- 仅关注不应自动进入今日工作或Header待办红点。

5. 全部工作
- 继续保留完整 Work Browser：搜索、关系/状态/优先级/事业筛选、更多团队/项目筛选、排序、卡片/列表；
- 这是大量工作管理入口，其他页面不机械复制这些控件。

6. 工作记录
- 默认进入“人员汇总”；
- 可切换 本周 / 本月 / 本年；
- 可切换 人员汇总 / 工作明细；
- 人员卡应显示：头像/姓名、工作总数、负责、参与、闭环、主要事业、主要项目、主要流程；
- 点击“查看记录”后，应显示该人员当前时间范围内的具体工作事实；
- 有头像时显示真实头像，无头像时显示首字占位。

7. 人员事实API（为人才之家预留）
/api/v1/work-home/people-summary?range=month

预期：
- factLayer = true
- performanceScore = false
- people[] 返回人员工作事实汇总
- observer关注关系不能被算成员工工作贡献。

8. 既有工作闭环回归
- 自己负责的工作仍可开始执行；
- 可添加执行说明/证据；
- 可提交完成；
- 创建者可验收；
- 美和AI复盘仍正常；
- Header工作提醒继续只反映真正需要本人处理的工作。

五、当前明确边界
- 工作记录第一版按Work Item最近活动/完成时间做本周/月/年归属；后续可以升级为事件级贡献时间统计。
- 工作记录提供事实，不直接生成绩效分、员工排名、奖金或晋升判断。
- 人才之家后续读取工作事实形成“工作贡献”；负责人再结合结果、质量、责任、协作、改进等做阶段评价。
- 关注重要动态的独立订阅流尚未单独开发；本版先把关注关系真实持久化和查询闭环跑通。
