# V1.9.37｜工作之家结构收口｜Candidate

基线：已部署并完成真实浏览器验收的 V1.9.36 WORK HOME BROWSER EXPERIENCE LOCK CANDIDATE。

## 本轮目标

今天只做工作之家 V2.0 最后一次结构收口，完成后冻结主结构，开发重心转入美和跨境真实业务闭环。本版不扩展知识之家、电子出版中心或人才之家工程，也不建立第二套工作数据。

## 锁定结构

正式 Sidebar 顺序：

`工作概览 → 今日工作 → 全部工作 → 我的关注 → 我的建议 → 我的创新 → 事业工作 → 团队工作 → 等待中 → 异常处理 → 待验收 → 工作记录`

其中四个高价值入口职责明确：

- 今日工作：聚焦今天最值得推进的工作，默认工作之家入口。
- 全部工作：需要搜索、比较、筛选大量工作时使用。
- 事业工作：按事业进入当前最关心的经营现场。
- 团队工作：从团队和成员视角查看工作分布、当前重点与推进情况。

四者仍然读取同一份 Work Item，只改变观察入口和默认 Query。

## 团队工作与工作记录

### 团队工作

- 新增正式独立入口，位于事业工作之后。
- 默认先看当前未闭环工作，也支持本周 / 本月 / 本年阶段视角。
- 人员信息优先读取既有统一人员目录/身份资料，不维护第二份头像、姓名、岗位数据。
- 点击某成员后进入同一 Work Item Browser，可继续搜索、筛选、列表/卡片和真实工作处理。
- 本页用于协同、工作分布和资源判断，不承担人才评价或绩效判断。

### 工作记录

- 回归“美和集团真实历史工作事实账本”。
- 只回看已完成 / 已取消 / 已归档工作及其结果、证据、验收和闭环事实。
- 人员汇总主入口移出工作记录，统一进入团队工作。
- 与人才之家的贡献、能力、绩效关系留待人才之家正式开发时再设计。

## 页面副标题与工作手册

- 每个正式工作目录拥有一句职责副标题，回答“什么时候应该来这个页面”，不堆功能清单。
- “查看工作手册”不再统一打开手册封面，而是通过 Page → Manual Section 深链定位到对应章节主标题。
- 当前已覆盖今日工作、全部工作、我的关注、建议/创新、事业工作、团队工作、等待中、异常处理、待验收、工作记录。
- 工作概览继续使用既有数字出版母版；本版只补齐章节锚点能力，不扩展知识之家/电子出版中心工程。

## 卡片 / 列表显示控制

显示控制统一为：

`列表 ｜ 卡片 ▼ ｜ 刷新`

卡片下拉支持 2 / 3 / 4 / 6 列：

- 保存用户最近的 view 与 card_columns 偏好。
- 用户决定显示偏好，系统负责最小可读性保护。
- Main 变窄时通过 container query 自动降为 4 / 3 / 2 / 1 列；空间恢复后仍保留用户原始偏好。
- 本版先在工作之家验证；未来其他对象浏览页是否统一采用该控制器，在对应页面升级时按同一原则复用。
