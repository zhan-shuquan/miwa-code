# AIONE V1.9.1 CANDIDATE｜第1阶段：Global Shell + Header上下文基线

**日期：2026-08-24**

## 本轮定位

本轮只执行当前架构优化计划的第1阶段，不扩具体工作台业务，不提前进入动态Sidebar/Aside重构。

核心目标是先把AIONE全局工作上下文稳定下来：

`公司 -> 事业 -> 人 -> 工作 -> 时间 -> 具体业务执行`

对应平台职责：

- 公司：Logo + AIONE，进入美和之家；
- 事业：当前事业上下文，可在美和跨境 / 美和批发之间切换；
- 人：当前登录用户与身份；
- 工作：工作之家；
- 时间：美和日历；
- 具体业务执行：继续由Sidebar承载，不挤入Header。

## 本轮正式变更

### 1. Header第一行顺序锁定

桌面Header第一行DOM与交互顺序统一为：

1. Logo + AIONE（公司 / 美和之家）
2. 当前事业
3. 当前用户
4. 工作之家
5. 美和日历
6. 分类之家
7. 商品之家
8. AI之家
9. 分析之家
10. 共享之家
11. 全局搜索
12. 通知
13. 帮助
14. 设置

其中1—5是AIONE工作上下文链；6—10是平台共享能力；11—14是全局工具。

通知不再插在“人 -> 工作 -> 时间”之间。

### 2. 当前事业进入Header

新增Header事业上下文入口，并与现有业务导航使用同一个事业状态源。

当前已有：

- 美和跨境
- 美和批发

切换事业时更新统一平台上下文，并进入该事业默认业务入口。

### 3. 新增平台上下文单一来源

新增：

`js/shell/platform-context.js`

统一管理：

- 当前事业状态；
- 事业本地持久化；
- 路由反向识别事业；
- `aione:platform-context-change`事件；
- 后续Sidebar / Aside动态生成所需的稳定上下文契约。

本轮只建立契约，不执行第2阶段的完整动态Sidebar/Aside生成。

### 4. Header共享入口收口

Header只保留当前已确认的核心共享入口：

`分类之家 -> 商品之家 -> AI之家 -> 分析之家 -> 共享之家`

客户之家、人才之家、收入之家、支出之家、知识之家等现有Route和数据能力没有删除，只是不再全部堆叠在Header第一行。后续在对应信息架构阶段确定正式入口关系。

### 5. 最新命名统一

活动Header继续统一使用：

- 工作之家
- 分析之家

不恢复旧名称“今日工作”“分析中心”。

### 6. 今日印象轻量化

Header“今日印象”继续保留日期、星期、时间、农历；节气与星座不再占用Header展示空间。

### 7. 移动端同步上下文逻辑

移动端同样体现：

`公司 -> 事业 -> 人 -> 工作之家 -> 美和日历`

平台共享能力顺序与桌面一致。

## 明确不在本轮做的事项

- 不重新设计各事业Sidebar的完整层级；
- 不把某一事业的Sidebar锁成全平台母版；
- 不重做Aside内容；
- 不重做分析之家图表体系；
- 不进入分类之家 / 商品之家 / 美和之家三级内容工程；
- 不修改Cloud SQL / Cloud Run正式运行方案；
- 不扩微信登录与外部Connector。

## 第2阶段入口条件

只有V1.9.1 Header与Global Shell人工预览确认后，才进入：

`事业 -> 工作台/之家/中心 -> 页面类型 -> 当前上下文`

驱动的动态Sidebar / Aside机制。
