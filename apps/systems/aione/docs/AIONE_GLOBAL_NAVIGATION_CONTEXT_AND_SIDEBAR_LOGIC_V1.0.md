# AIONE全局导航与页面上下文逻辑说明 V1.0

- 文档ID：`KNOW-AIONE-NAV-CONTEXT-V1`
- 归属：知识之家 → 帮助中心
- 状态：正式锁定（Header核心逻辑与区域职责）；Sidebar具体菜单配置进入第2阶段验证
- 生效日期：2026-08-24
- 适用系统：美和AIONE一体化工作平台

## 1. 文档目的

本说明用于统一AIONE全局导航、当前上下文、Sidebar、Main、Aside与页面层级之间的关系，避免后续随着事业、工作台、之家、中心和页面数量增加而出现导航重复、入口漂移、左右边栏污染和页面母版失控。

AIONE导航设计不按“哪个按钮更常用就放前面”处理，而按业务与认知顺序建立稳定逻辑。新增按钮、事业、工作台或全局能力时，必须先判断其职责，再决定位置。

## 2. AIONE第一行的底层顺序

AIONE第一行的核心上下文顺序正式锁定为：

**公司 → 事业 → 人 → 工作 → 时间 → 具体业务执行**

映射到当前系统：

1. **公司｜Logo + AIONE**
   - 代表美和集团与AIONE平台身份。
   - 点击进入“美和之家”。
   - 回答：我正在什么公司与平台中工作？

2. **事业｜当前事业**
   - 例如：美和跨境、美和批发。
   - 是当前业务上下文，不是普通快捷按钮。
   - 事业切换后，后续业务导航、工作台、数据范围与辅助信息应随上下文变化。
   - 回答：我现在在哪一个事业中工作？

3. **人｜当前用户 / 身份 / 岗位**
   - 展示当前登录用户及必要的岗位、职级信息。
   - 人是工作、权限、任务、责任与结果归属的主体。
   - 回答：现在是谁在这个事业中工作？

4. **工作｜工作之家**
   - “今日工作”正式统一为“工作之家”。
   - 负责当前用户的工作、任务、待办、上下指派与执行入口。
   - 回答：我现在要做什么？

5. **时间｜美和日历**
   - 与工作之家天然成组。
   - 工作之家回答 What，美和日历回答 When。
   - 回答：这些工作什么时候发生？

6. **具体业务执行｜Sidebar + Main**
   - 不把9个工作台继续塞入Header。
   - 进入具体事业和业务后，由Sidebar提供稳定业务路径，由Main完成实际工作。
   - 回答：这件工作具体在哪个业务流程中处理？

因此，Header负责**建立上下文**，Sidebar负责**进入业务**，Main负责**完成工作**。

## 3. Header第一行完整职责分组

### 3.1 第一组：工作上下文链

顺序固定：

**Logo + AIONE → 当前事业 → 当前用户 → 工作之家 → 美和日历**

这5项属于AIONE工作上下文核心，不因为页面、事业或个人偏好随意重排。

### 3.2 第二组：跨业务共享“之家”

当前统一顺序：

**分类之家 → 商品之家 → AI之家 → 分析之家 → 知识之家 → 共享之家**

这组不是业务流程节点，而是跨工作台共享的长期认知、对象、能力、知识与资源入口。

职责分别为：

- **分类之家**：经营分类的定义、层级、责任、关联与经营状态。
- **商品之家**：商品主对象及其跨事业、跨店铺、跨流程关联。
- **AI之家**：AI人才、AI能力、Agent、自动化、证据与治理。
- **分析之家**：经营事实、指标、趋势、异常、效率与分析结果。
- **知识之家**：方法论、标准、制度、SOP、业务知识、培训与帮助内容的正式知识源。
- **共享之家**：文件、账号、素材、代码、数据资产等可共享客观资源入口。

### 3.3 第三组：全局工具

- 全局搜索
- 通知
- 帮助快捷入口
- 设置

这组属于工具，不参与“公司→事业→人→工作→时间”的上下文排序。

## 4. “帮助之家”正式取消

AIONE不再设立“帮助之家”。

正式关系为：

**知识之家 → 帮助中心 → 具体帮助文档**

原因：

1. 帮助内容本质上属于正式知识，不应与知识体系分离维护。
2. 页面说明、字段说明、流程说明、系统使用方法都应该“一份知识，多处调用”。
3. Help入口可以保留为全局快捷按钮，但它只是**快速进入知识之家中的帮助中心**，不是一个独立“之家”。
4. 后续页面内的“？”、“帮助”、“字段说明”可以按上下文直接深链到帮助中心的具体知识文档或锚点。

因此：

- `知识之家`是一级共享知识入口。
- `帮助中心`是知识之家内部的一个中心/分类。
- `帮助`图标只是快捷方式。

## 5. 新增Header按钮时的排序规则

以后即使Header增加入口，也不能按视觉空位或个人感觉插入，必须先判断职责：

### A. 属于工作上下文吗？

如果是公司、事业、人、工作、时间中的核心上下文，进入第一组，并严格按因果顺序排列。

### B. 属于跨业务长期共享对象/能力吗？

如果是长期共享认知、对象、能力、知识或资源，进入“之家”组。

### C. 属于工具吗？

如果是搜索、通知、帮助、设置等跨平台工具，进入右侧工具区。

### D. 属于具体业务执行吗？

不进入Header，进入当前事业的Sidebar或当前页面Main。

核心原则：

**位置由职责决定，不由曝光率决定；全局能力有固定位置，业务执行有稳定路径。**

## 6. Sidebar正式生成原则

Sidebar不再作为全平台统一固定业务菜单锁死。

平台只锁定Sidebar的：

- 视觉规范
- 宽度
- 层级样式
- 展开/收起行为
- 当前项状态
- 响应式规则
- 生成逻辑

Sidebar具体内容必须根据以下上下文生成：

**事业 → 当前模块（工作台/之家/中心）→ 页面类型 → 当前上下文**

### 6.1 事业切换只归Header

“当前事业”的切换控制正式归Header。

Sidebar不再重复放置“美和跨境 / 美和批发”切换按钮，避免同一职责出现两个入口。

在具体事业工作台页面，Sidebar可以显示当前事业名称作为只读上下文标题，但不重复承担切换功能。

### 6.2 工作台页面的Sidebar

当进入具体事业工作台时，例如“美和跨境 → 选品工作台”：

Sidebar应显示：

- 当前事业名称（上下文标题，可简化）
- 当前事业的工作台入口
- 当前工作台的二级业务节点（按需展开）
- 当前所在页面高亮

目的：快速在同一事业的业务流程之间移动。

### 6.3 全局“之家 / 中心”页面的Sidebar

当进入“店铺之家、分类之家、商品之家、AI之家、分析之家、知识之家、共享之家”等全局模块时：

**不得继续显示美和跨境9个工作台或美和批发流程。**

Sidebar应切换为当前“之家 / 中心”的本地导航，例如：

**分类之家**
- 分类概览
- 分类目录
- 深耕分类
- 分类责任
- 品牌中心
- 分类标准

**知识之家**
- 知识概览
- 帮助中心
- 方法论
- 标准
- 制度
- SOP
- 业务知识
- 培训资料
- 系统 / AI知识

这正是“Header建立全局上下文，Sidebar只服务当前模块”的核心体现。

### 6.4 工作之家 / 美和日历等特殊全局页面

这类页面不应机械显示事业工作台菜单。

Sidebar只在确有价值时显示本页面的本地导航，例如：

- 工作之家：我的工作、待处理、我发起的、已完成、相关工作台
- 美和日历：日历概览、我的日程、团队日程、重要节点

如果没有足够有价值的本地导航，可以保持轻量，不为了“填满Sidebar”制造菜单。

### 6.5 三级详情页面

三级页面聚焦具体对象或具体内容，例如：

- 分类详情
- 商品详情
- 知识文档
- 工作任务详情
- 分析明细

Sidebar应优先保留其父级模块的稳定导航，并突出当前对象所在位置；需要快速返回时提供明确返回路径，而不是重新展示无关事业菜单。

## 7. Main的统一与变化

AIONE统一的是页面母版与组件语言，不是强迫所有Main都长得一样。

### 业务执行型Main

可使用：

- KPI
- 状态
- 队列
- 卡片
- 列表
- 表单
- 快捷操作
- 流程节点

### 分析型Main

可大量使用：

- KPI
- 折线图
- 柱状图
- 漏斗图
- 分类占比
- 排行榜
- 热力图
- 异常指标
- AI分析摘要

### 内容型Main

用于：

- 方法论
- 规划
- 制度
- SOP
- 帮助文档
- 培训内容

核心原则：

**母版统一，内容按职责变化；底层复杂，前台简单。**

## 8. Aside的职责

Aside不作为第二个Main，也不成为固定任务中心。

它根据当前页面、当前对象和当前操作动态显示最有价值的辅助信息，例如：

- 当前上下文摘要
- 风险与异常
- 页面帮助
- 字段解释
- AI提示
- AI秘书
- 关联对象

没有高价值内容时可以保持轻量或收起。

## 9. 页面层级与导航关系

### 一级

平台、事业、核心全局入口。

### 二级

工作台根页面、之家概览、中心/聚合页面。

负责组织、聚合和进入下一步。

### 三级

具体业务对象、内容正文、明细、报告或分析。

负责把“一件具体事情”展示和处理完整。

因此长期遵循：

**二级负责组织，三级负责展开。**

## 10. 三个典型示例

### 示例A｜美和日历

Header：

`AIONE → 美和跨境 → 当前用户 → 工作之家 → 美和日历`

Sidebar：显示日历自身本地导航，或保持轻量。

Main：日历与日程。

Aside：重要日程、AI日程辅助、上下文提醒。

### 示例B｜店铺之家

Header继续保留当前事业上下文，但“店铺之家”是跨业务全局对象页面。

因此Sidebar：

- 不显示“美和跨境9工作台”
- 不显示“美和跨境 / 美和批发”切换按钮
- 改为店铺之家自己的本地导航

### 示例C｜分类之家

Header：分类之家高亮。

Sidebar：分类之家本地结构。

Main：分类概览、分类卡片/列表、分类经营信息。

从具体分类需要查看商品时，通过内部路由进入商品之家对应商品；反向也可由商品回到分类。

## 11. 工程实现约束

1. Header必须保持单一来源，不允许页面私自复制Header。
2. 当前事业状态必须保持平台级单一来源。
3. Sidebar不得再次维护独立的事业切换状态。
4. 页面不得为了“快速入口”重复完整导航。
5. “帮助之家”不得重新出现；所有帮助知识归“知识之家 → 帮助中心”。
6. 新增全局入口必须先完成职责分类再确定位置。
7. 事业工作台菜单与全局之家菜单必须按上下文切换，不能同时叠加污染页面。
8. Header与Footer可以作为平台级稳定架构；Sidebar与Aside只锁定职责和生成规则，不锁死具体业务内容。

## 12. 当前结论状态

### 正式锁定

- 公司 → 事业 → 人 → 工作 → 时间 → 具体业务执行
- Header负责建立上下文
- Sidebar负责进入当前业务/模块
- Main负责完成主要工作
- Aside负责上下文辅助
- 当前事业切换归Header
- 工作之家、美和日历的顺序
- 分类之家、商品之家、AI之家、分析之家、知识之家、共享之家属于共享“之家”组
- 帮助之家取消
- 帮助中心归知识之家
- 全局之家页面不得继续展示无关事业工作台Sidebar

### 第2阶段验证

- 各类型页面Sidebar的具体菜单配置
- 工作台内部二级节点展开方式
- 全局之家Sidebar的统一视觉结构
- 特殊页面Sidebar轻量化规则
- 移动端Sidebar / Drawer对应行为

---

**最终原则：Header先把“我是谁、在哪个事业、要做什么、什么时候做”讲清楚；Sidebar再告诉用户“这件事具体去哪里处理”。只要这两层不混淆，AIONE后续增加更多事业、工作台、之家、中心和三级页面，也不会重新陷入导航混乱。**
