# 美和AI办公室架构 V1.0

**版本状态：** 验证中  
**首个验证办公室：** 会长兼董事长AI办公室  
**首个验证人：** 对应人类岗位负责人本人  
**所属系统：** 美和AIONE一体化工作平台

## 1. 核心定位

美和AI体系分为三层：

1. **AI之家**：AI能力与AI资产供给层，管理AI人才、AI岗位、Skill、Agent、Connector、Tool/API、模型、自动化、成本与真实验证结果。
2. **岗位AI办公室**：AI工作的组织与使用单位，围绕一个真实人类岗位的目标、责任与业务上下文组织AI工作。
3. **AI秘书**：岗位AI办公室最高AI调度层，负责受领目标、读取上下文、按美和9要素理解业务、调用AI人才/知识/数据/Tool并汇报结果。

最终业务责任始终归对应**人类岗位负责人**。AI秘书是最高AI长官，不替代人类最终责任。

## 2. 首批预设岗位AI办公室

- 会长兼董事长AI办公室（验证中）
- 跨境负责人AI办公室（预设）
- 批发负责人AI办公室（预设）
- 运营岗位AI办公室（预设）
- 采购岗位AI办公室（预设）
- 设计岗位AI办公室（预设）
- 客服岗位AI办公室（预设）

这些办公室共用一套AI办公室底座，不分别开发七套系统。差异来自岗位Context、责任范围、可调用AI岗位与Tool集合。

## 3. AI秘书的统一业务语言

AI秘书使用固定顺序的**美和9要素**理解上下文：

`目标｜人｜物｜事｜平台｜时间｜钱｜信息｜结果`

组件顺序固定；分析时可根据当前目标从不同要素切入。

执行基本链：

`目标 → 上下文 → 9要素完整性 → 业务对象 → 流程状态 → 正式知识/规则 → Tool → 人类确认（需要时） → 结果 → 工作证据`

## 4. AIONE中的交互方式

AI秘书不是独立外部GPT入口。其常驻交互界面位于AIONE右侧Aside，并支持：

- 收起
- 标准
- 展开

展开采用覆盖式工作面板，避免长期压缩Main。

页面本身不为了体现AI而到处增加AI按钮；业务页面负责对象、字段、流程、状态和结果，AI秘书负责跨页面理解与执行。

## 5. AI办公室正式页面

`#/ai-office` 使用AIONE标准业务母版，用于集中管理：

- 岗位AI办公室
- 人类负责人
- AI秘书
- 责任范围
- 预设AI岗位
- 当前状态
- 后续AI工作、待确认、执行证据与结果

右侧AI秘书负责“现在就工作”；AI办公室页面负责“集中管理AI工作”。

## 6. 人类确认原则

当前V1.8首批Tool仅开放读取和分析；写动作由AI秘书提出Proposal，必须由已认证的人类负责人确认后才能执行。

当前首个可确认写动作：

- 创建工作事项

后续任何高风险能力（重大人事、薪酬、资金、正式制度、批量关键状态、删除正式数据等）继续保持人类确认。

## 7. AI人才体系

AI岗位可以提前预设，AI人才可通过AI Assignment进入不同岗位AI办公室。AI人才可跨办公室共享，不复制能力。

未来关系：

`AI岗位 → AI人才 → AI任职(AI Assignment) → 岗位AI办公室 → AI秘书统一调度`

AI岗位的预设不等于立即产生成本；真实模型/API/软件/监督成本仍应进入AI成本与工作证据体系。

## 8. 第一阶段验证目标

会长兼董事长AI办公室优先验证：

- AI是否知道当前人类身份与岗位办公室
- AI是否知道当前页面与业务上下文
- 是否能读取工作、日程、通知等AIONE事实
- 是否能读取数据库工作事实（数据库迁移后）
- 是否能查找内部知识路由（数据库迁移后）
- 是否能按美和9要素形成有依据的判断
- 是否能选择和调用AIONE Tool
- 写入是否严格等待人类确认
- 是否形成AI执行日志与后续工作证据

V1.8是**执行链路验证候选**，不是完整AI办公室最终版。
