# BASELINE V1.9.33｜工作之家 V2.0 结构升级 Candidate

日期：2026-08-27

## 本版定位

V1.9.33 不再把工作之家缩成“个人任务中心”，而是按集团长期尺度建立：

- 工作概览：统一数字出版物工作手册；
- 今日工作：只回答“现在先做什么”；
- 全部工作：集团内部统一 Work Item 浏览入口；
- 我的关注：跨事业主动建立相关性，不等于接手任务；
- 事业工作：按美和跨境、美和批发、美和采购代理、美和物流、美和留学、美和不动产、美和商务咨询、美和品牌聚合；
- 等待与阻塞 / 待验收 / 工作记录：负责闭环异常、验收与历史。

核心继续坚持：**后台复杂，前台简单；一份工作事实，多种视图。**

## 1. Sidebar 结构

正式前台结构改为：

1. 工作概览
2. 今日工作
3. 全部工作
4. 我的关注
5. 事业工作（树形）
6. 等待与阻塞
7. 待验收
8. 工作记录

`我的工作` 不再作为正式 Sidebar 入口，保留为兼容路由；个人责任、参与、创建、关注等关系进入 Main 筛选。

## 2. Work Browser

除今日工作外，大量工作事项统一采用 Work Browser：

- 卡片 / 列表双视图；
- 搜索；
- 关系筛选；
- 状态筛选；
- 优先级筛选；
- 事业筛选；
- 团队 / 项目扩展筛选；
- 美和AI建议优先 / 截止时间 / 最近更新 / 优先级排序。

卡片与列表读取同一 Work Item，不创建第二套数据。

## 3. 关注机制

复用既有 `work_item_participants` 表的 `observer` 角色，不新增重复关注表：

- `POST /api/v1/work-home/:id/follow`
- `DELETE /api/v1/work-home/:id/follow`
- `GET /api/v1/work-home?scope=following`

关注的含义：持续看到工作动态，不等于负责人、参与者或执行权限。

重要边界：**关注项不会因为“关注”自动进入今日工作或 Header 待办提醒。** 透明与关注不等于推送。

## 4. 公司内部可见性

`GET /api/v1/work-home?scope=all` 支持公司内部工作透明：

- 默认 `metadata.visibility = company`；
- `private / restricted / sensitive` 不进入全公司视图；
- `metadata.sensitive=true` 同样按敏感事项处理；
- 负责人、创建者和正式参与者仍可按既有关系读取。

执行、提交完成、验收等写权限保持既有规则，不因可见范围扩大而扩大。

这正式落实：**看得到 ≠ 要处理 ≠ 能操作。**

## 5. 事业归属

新由美和AI从业务页面创建的工作，会根据来源 Route 写入：

- `metadata.businessCode`
- `metadata.visibility = company`

当前首批确定性识别：

- 跨境九工作台 → `crossborder`
- 批发业务 Route → `wholesale`

历史 Work Item 未带事业信息时不会伪造归属，统一保留为“集团 / AIONE”或待后续补齐。

## 6. 工作概览正式出版化

V1.9.32 的“出版物风格”被替换为真正继承 `miwa-publication-master.js/css` 的数字书册：

- 正封面 + 封底；
- A4 纵向书页；
- 宽屏双页，空间不足单页；
- 打印 / 导出 PDF；
- 统一页码、Topline、Footer、版心、章节、结论条。

《美和工作手册》共 8 章：

1. 工作之家是什么
2. 为什么需要工作之家
3. 美和工作9问
4. 工作如何流动
5. 人与美和AI
6. 工作如何组织
7. 工作之家与美和日历
8. 当前工作动态

## 7. 不改变的既有闭环

完整继承并继续验证：

- 美和AI Proposal → 人工确认 → Work Item；
- 开始执行；
- 工作证据；
- 提交结果；
- 创建者验收；
- 美和AI复盘；
- Header 工作提醒；
- `work_items / work_evidence / result_facts / business_events` 同一事实链。

## 8. 当前边界

- 关注已持久化并可查看最新动态，但尚未建立单独“关注更新通知”订阅事件；这是刻意边界，避免关注自动变成待办。
- 团队 / 项目筛选已进入前台组件；只有 Work Item 已存在相应元数据时才显示真实选项，不使用示例数据。
- 美和日历本版继续保留“同一 Work Item 的时间投影”架构，不在本版新建第二套日历任务。

## 结论

V1.9.33 的目标不是一次把页面做得最简，而是先把未来集团尺度的完整工作骨架建立起来，再依据真实使用逐步删减和优化。
