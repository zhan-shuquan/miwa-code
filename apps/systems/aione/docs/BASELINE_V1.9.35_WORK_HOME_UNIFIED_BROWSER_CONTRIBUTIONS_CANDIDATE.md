# V1.9.35｜工作之家统一工作事项一览 + 组织互动入口｜Candidate

基线：V1.9.34 WORK HOME CONTEXT + RECORDS UPGRADE CANDIDATE。

## 本轮锁定方向

1. Sidebar按人的操作路径组织：工作概览 → 今日工作 → 全部工作 → 我的关注 → 我的建议 → 我的创新 → 事业工作 → 等待中 → 异常处理 → 待验收 → 工作记录。
2. Header“工作之家”默认进入今日工作，不再默认打开工作手册。
3. 今日、全部、关注、事业、等待、异常、待验收继续共用同一 Work Item Browser，只改变预设查询。
4. “全部工作”保留完整搜索/筛选/排序；高频筛选常驻，团队/项目进入“更多筛选”；“重置”恢复当前入口默认条件。
5. 点赞前台位置预留，但不伪造团队点赞事实；关注Backend本轮不作为阻塞项。
6. 工作记录：人员汇总支持卡片/列表；工作明细直接复用 Work Item 的卡片/列表展示；人员资料优先读取统一用户目录，缺失时回退内测身份/首字头像。
7. “我的建议 / 我的创新”个人入口建立；集团归口分别为美和之家 → 经营与战略 → 建议中心 / 创新中心。正式多用户投稿Backend后续接入。
8. 《美和工作手册》按最新Sidebar补齐建议、创新、事业、等待、异常、验收、工作记录的使用指南。

## 数据责任边界

- Work Item仍是工作事项唯一事实源。
- Suggestion / Innovation未来作为独立贡献对象，不在本版本伪装成Work Item。
- 工作记录是事实层；人才之家解释贡献；绩效不是工作数量直接换算。
- 点赞是互动信号；关注是动态订阅；浏览是阅读事实，三者不混同。

## 本轮不做

- 不新增点赞Backend。
- 不修改关注Backend与数据库结构。
- 不新增Suggestion / Innovation正式数据库表和提交接口。
- 不修改既有Proposal → Work Item → 执行 → 证据 → 验收 → AI复盘闭环。
