# AIONE Work + Product Unified CURRENT｜V1.0

状态：CURRENT 候选，等待业务负责人验收后继续开发
日期：2026-09-03
适用项目：美和AIONE一体化工作平台（AIONE）

## 1. 唯一验收流程

从本版本开始，AIONE开发统一回到一条连续流程：

Product Truth讨论与收口
→ 写入Repo CURRENT
→ 在同一真实AIONE Shell中实现
→ https://aione-test.miwa-happyhouse.com/ 验收
→ 有问题回退到上一稳定节点修正
→ 验收稳定后再由总工程师决定推进main

规则：
- aione-test.miwa-happyhouse.com 是当前唯一真实验收现场。
- 不再把多个独立HTML、独立预览分支同时作为“最新版本”。
- 旧实验分支保留历史验证价值，但不继续独立演化。
- 每天可以讨论和推进一点；出现错误允许回到上一稳定内容重新开始。
- main继续作为唯一稳定技术基线，不直接作为实验区。

## 2. 工作之家平台定位

工作之家是员工日常工作的默认入口。

核心原则：
> 工作之家负责“人做什么”；各业务之家负责“业务事实是什么”。

员工原则上不需要为了完成日常工作，在选品中心、设计中心、测样中心、采购中心、运营中心、客服中心之间来回切换。

工作可以跨事业、跨业务类型、跨时间自由安排；工作做完为止。业务归属、事业、团队、对象、状态、负责人等使用字段和筛选表达，不再为了不同观察范围重复建页面。

## 3. 工作之家 CURRENT 左侧结构

1. 工作概览
2. 我的工作
3. 我的安排
4. 我的互动
5. 我的学习
6. 我的建议
7. 我的创新
8. 我的总结
9. 全部工作
10. 工作记录

废止为长期独立导航入口：
- 团队工作
- 事业工作

原因：团队、事业、本周、本月、负责人、状态等都属于同一Work事实的筛选维度。

## 4. 我的互动 CURRENT

“我的互动”是聚合入口，基本互动类型必须完整保留：

1. 我的关注
2. 我的收藏
3. 我的点赞
4. 我的评论
5. 我的@
6. 我的讨论
7. 我的转发
8. 其他后续平台级互动

底层不为8类互动复制业务对象。互动关系由统一Interaction/Reaction/Comment/Mention/Share等平台能力承载，前台只是不同View。

## 5. 我的工作 CURRENT

“我的工作”不是单一任务清单，而是当前用户全部工作事实的个人View。

工作类型可以包括：
- 选品
- 设计
- 测样
- 采购
- 上架
- 运营
- 客服
- 其他后续工作类型

同一个员工可以在同一天跨业务工作，不要求固定进入某个业务工作台。

系统自动记录的字段不要求人工重复填写，例如：
- 当前用户/负责人
- 创建人
- 创建时间
- 工作开始/更新时间
- 事业归属
- 工作类型
- 关联对象
- 系统来源
- AI/自动化处理状态

人工只填写真正不能由系统、API、继承、规则或AI稳定得到的必要字段。

## 6. 全部工作 CURRENT

“全部工作”是AIONE统一工作事实账本和管理观察入口。

所有用户的工作最终都汇入同一Work Model。

管理者通过字段筛选查看：
- 负责人
- 安排人
- 事业
- 团队
- 工作类型
- 状态
- 优先级
- 时间范围
- Product / SKU / 客户 / 供应商 / 店铺 / 订单等关联对象

不再为了“团队工作”“事业工作”维护第二套页面或第二套数据。

此模型为后续业绩、成果、产能、效率、闭环率、返工、AI参与、自动化覆盖等分析提供统一事实来源。

## 7. 选品架构重大收口

取消“选品中心”作为员工日常独立工作中心。

选品本质是一种Work Type。

标准入口：
> 工作之家 → 我的工作 → 选品

这里就是当前用户真实的“我的选品”工作表。

选品工作允许当天只完成机会收集与判断，不要求立即创建正式商品。

## 8. 我的选品 CURRENT

“我的选品”采用简单、连续、适合长期累积的表格形式。

核心原则：
> 能自动的全部自动；人工只填必要字段。

系统自动字段包括但不限于：
- 选品人
- 选品时间
- 创建时间
- 所属事业
- 来源平台（可识别时）
- 处理状态
- 批次/来源上下文
- 后续Opportunity / Product关联ID

人工输入按实际自动化能力动态减少。

### API可用时

员工可能只需要填写：
- 商品链接
- 必要备注

系统/API/AI继续补齐：
- 商品名称
- 图片
- 供应商
- 采购价
- SKU/规格
- 分类建议
- 属性
- 其他可稳定识别事实

### API不可用时

仍使用同一张表、同一套字段模型，只要求用户补充真正必要的字段，例如：
- 商品链接
- 商品简称
- 三级分类
- 来源
- 采购价
- 必要规格/图片/备注

不建立“API版选品页面”和“人工版选品页面”两套系统。

## 9. 选品录入方式 CURRENT

“批量选品”不作为长期独立工作台，只是“我的选品”的一种录入方式。

支持方向：
- 单条新增
- 直接粘贴链接
- 一次粘贴多条链接自动拆行
- Excel/CSV导入
- API导入
- 后续AI发现商品机会

之前讨论的“个人Google选品表”不再作为默认方案。

Google Sheet可以作为特殊外部入口保留未来可能性，但员工日常选品优先直接在工作之家完成。

## 10. Opportunity 与 Product CURRENT

选品和正式商品建立是两个独立但可衔接的动作。

选品：
> 商品机会发现 / 判断

新建商品：
> 正式Product建立

员工可以：
- 完成选品后结束当天工作
- 单个Opportunity转为商品
- 批量选择Opportunity转为商品
- 跳过选品，直接新建Product
- 批量导入正式商品

Product不强制必须来自Opportunity。

`source_opportunity_id`为可选关联字段。

## 11. 商品之家定位

商品之家不再承担员工日常“到处点工作台做事”的角色。

商品之家主要负责正式业务事实、规则和跨对象管理。

员工在工作之家完成工作后，通过Domain/Application Service自动更新商品域正式数据。

例如：
- 我的选品 → ProductOpportunity / Product
- 我的测样 → Sample Result / Product-SKU测样状态
- 我的设计 → Design Asset / Version / Product设计状态
- 我的采购 → Purchase / Supplier Relation / Inventory相关事实
- 我的运营 → Operation事实
- 我的客服 → Customer Service事实

工作数据与商品数据不复制成两份。

## 12. 商品中心 CURRENT

商品中心管理正式Product与SKU，不管理选品过程。

当前水平页签：
> 全部商品｜SKU｜设置

Product与SKU仍为完整业务对象入口，不是简单列表行。

正式Product规则：
> 1 Product : 1..N SKU

正式Product至少有1个SKU。

单规格商品也自动生成默认SKU。

Product ID：
> MH0000001

SKU ID：
> MH0000001-01

ID语义自由、全局唯一、不可复用。

## 13. SKU Generator CURRENT

SKU Generator是商品平台级共享能力，不是某个页面的局部工具。

所有Product建立路径最终统一进入：

Product Draft
→ SKU Generator
→ Product + SKU

主要调用场景：
- Opportunity转商品
- 批量Opportunity转商品
- 直接新建商品
- 批量商品导入
- API商品导入
- AI商品识别
- 已有Product新增变体

标准三步：
1. 确认商品
2. 确认规格
3. 确认SKU

原则：
> API事实 ＞ 确定性规则 ＞ AI建议 ＞ 人工最终确认

SKU Generator生成候选SKU组合，不盲目生成全部笛卡尔积。

常见2维规格可用矩阵；复杂规格使用列表。

支持方向：
- 禁用不可能组合
- 批量原产国
- 批量初始状态
- 批量图片关联
- 自动继承Product级事实
- SKU图片优先读取外部API事实/已有素材，再AI匹配，最后人工纠正
- JAN/GTIN只显示编码状态，正式编码管理归编码中心

## 14. Product Intake统一模型

选品导入和商品导入底层使用同一套：
> Product Intake Schema

前台可以有不同的简化模板，但不允许维护两套逐渐漂移的数据Schema。

所有入口最终映射到统一商品基础事实，再根据业务目的进入：
- Opportunity
或
- Product Draft

## 15. 工作结果回写业务域的统一原则

底层统一遵循：

Object
→ Event
→ Rule / AI
→ Action
→ Human Task（必要时）
→ Result
→ Object Update
→ Next Event

员工不需要自己决定“这个结果下一步应该去商品中心哪个页面”。

系统根据Work Type和关联对象自动回写对应Domain事实。

需要查看完整正式资料时，在工作之家提供上下文快捷按钮，例如：
- 查看正式商品
- 查看SKU
- 查看供应商
- 查看设计资料
- 查看订单

而不是要求员工自行在多个之家中寻找。
