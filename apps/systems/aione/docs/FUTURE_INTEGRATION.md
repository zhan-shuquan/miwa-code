# 后续统一接入方案

## 1. 一级页面：选品工作台

取得最新真实代码压缩包后：

1. 只提取选品工作台 Main 的 HTML、页面 CSS 与页面 JS。
2. 放入 `pages/selection-workbench/`。
3. 复用当前公共 Shell，不复制 Header、Sidebar、Aside 或 Footer。
4. 将页面样式从旧 `components.css` 中彻底分离。
5. 依据已锁定的一级页面四区结构验证：页头、页面概览、核心区、辅助区。

## 2. 业务模块：选品记录

取得最新真实代码压缩包后：

1. 放入 `modules/selection-record/`。
2. 选品记录保留完整业务事实、证据和历史；商品机会卡片只读取摘要。
3. 模块通过同一数据对象被选品工作台、详情页、报告和后续 AI/API 调用。
4. 不在卡片与选品记录之间重复维护字段。

## 3. 统一后的关系

```text
美和系统公共 Shell
├─ Header
├─ Primary Navigation
├─ Aside
└─ Footer
       ↓ 共用
选品工作台（一级页面／Main）
       ↓ 调用
选品记录（业务模块／完整数据对象）
       ↓ 投影
商品机会卡片、列表、报告、AI判断接口
```

## 4. 当前不能提前做的事

- 不把恢复包中的旧选品 CSS 当作最终页面代码。
- 不根据截图重新拼装完整选品工作台。
- 不根据聊天记忆猜测选品记录字段或交互。
- 不让后续页面重新复制公共 Shell。

因此，后续可以统一，而且现在建立的结构正是为了让统一发生时不再破坏全局框架。
