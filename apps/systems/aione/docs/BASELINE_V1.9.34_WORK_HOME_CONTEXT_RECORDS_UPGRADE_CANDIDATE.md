# BASELINE V1.9.34｜工作之家 V2.0 场景减法与工作记录升级 Candidate

日期：2026-08-27

## 本版定位

V1.9.34 不新增第二套任务系统，而是在 V1.9.33 集团级工作骨架上继续落实两条已经确认的原则：

1. **底层组件统一，前台按场景减法。** 今日工作、我的关注、事业工作等继续读取同一 Work Item，但不同页面只展示完成当前目的所需的控制项。
2. **工作记录是事实层，不是绩效评分。** 工作之家记录谁在什么时间、事业、项目和流程中承担/参与了哪些工作，为人才之家“工作贡献”、分析之家产能和知识之家方法沉淀提供证据。

核心继续坚持：**后台复杂，前台简单；一份工作事实，多处调用。**

## 1. 今日工作 / 我的关注共用工作事项一览

`今日工作` 与 `我的关注` 不再机械继承“全部工作”的完整筛选器，而使用同一套轻量 Work Item List：

- 简单搜索；
- 卡片 / 列表切换；
- 刷新；
- 同一工作详情；
- 同一关注/执行权限边界。

差别只在预设查询：

- 今日工作：当前用户相关工作中由今日队列规则选出的事项；
- 我的关注：`scope=following` / `observer` 关系的事项。

“我的关注”不显示与页面目的无关的 KPI、关系/优先级/事业全套筛选。

## 2. 全部工作仍保留完整 Work Browser

`全部工作` 继续承担大量工作管理入口，因此保留：

- 搜索；
- 关系 / 状态 / 优先级 / 事业筛选；
- 团队 / 项目扩展筛选；
- 排序；
- 卡片 / 列表。

这明确区分：**统一组件不等于所有页面显示同一组按钮。**

## 3. 关注真实闭环诊断

V1.9.33 实测出现 `not_found`，说明前端已经具备关注UI，但当前实际 Backend 未命中对应接口。V1.9.34 增加：

- `GET /api/v1/work-home/capabilities`，用于确认实际 Backend 已部署到 V1.9.34；
- 保留 `POST /api/v1/work-home/:id/follow` / `DELETE .../follow`；
- 前端遇到404时明确提示“Backend 尚未部署/重启”，不把本地收藏伪装成正式关注成功。

正式验收必须做到：关注 → 数据库写入 → 刷新仍为已关注 → 我的关注可见 → 取消关注成功。

## 5. 帮助中心与场景手册关系

新增 `WORK_HOME_MANUAL_V2` 聚合入口。正式知识正文不在帮助中心复制第二份：

`具体页面 → 概览/场景数字手册 → 帮助中心统一聚合、搜索、AI调用`

这继续执行“一份知识，多处调用”。

## 6. 工作记录：人员汇总 + 工作明细

工作记录首页新增：

- 时间：本周 / 本月 / 本年；
- 视图：人员汇总 / 工作明细；
- 人员卡：头像、姓名、工作总数、负责、参与、闭环；
- 主要事业；
- 主要项目；
- 主要流程；
- 点击人员查看当前时间范围的具体工作事实。

关注者 `observer` 不计入人员工作贡献。

重要边界：**工作数量只用于理解工作量和进入明细，不直接转换为绩效分数。**

## 7. 为人才之家预留可复用事实接口

新增：

`GET /api/v1/work-home/people-summary?range=week|month|year`

返回当前可见工作事实的人员聚合：

- totalCount
- responsibleCount
- participatedCount
- closedCount
- businesses
- projects
- workbenches
- lastWorkAt

接口显式返回 `factLayer:true`、`performanceScore:false`，让人才之家后续读取事实形成“工作贡献”，而不是从工作数量直接做人员好坏判断。

## 8. 人才 / 分析 / 知识的长期关系

工作之家负责事实：

`Work Item → 执行 → 结果/证据/验收 → 工作记录`

下游：

- 人才之家：工作贡献、能力画像、阶段评价证据；
- 分析之家：真实工作量、产能、效率、AI参与与返工；
- 知识之家：重复工作中识别 SOP、Skill、自动化和方法资产。

## 9. 不改变的既有闭环

完整继承：

- 美和AI Proposal → Human Confirm → Work Item；
- 开始执行；
- 工作证据；
- 提交结果；
- 创建者验收；
- 美和AI复盘；
- Header 工作提醒；
- 数字出版物统一母版；
- 公司可见读取与写权限分离。
