# 美和AIONE字段标准 V1.0

**标准状态：** 验证中（第5阶段候选）  
**适用范围：** 美和AIONE一体化工作平台的二级页面、业务对象、内容对象、导入导出、AI Tool Layer、审计与未来数据库  
**核心原则：** 一份字段语义，多处调用；页面名称可以调整，`fieldCode` 一旦正式锁定不得随意改变。

## 1. 字段为什么必须先标准化

AIONE下一阶段要进入数据库与后端。字段如果仍散落在页面代码里，数据库、AI、导入导出、帮助、审计会出现多套口径。V1.0先把字段变成独立的业务语义资产，再由页面、API和数据库共同调用。

## 2. 每个字段的标准元数据

每个正式字段至少包含：

- `fieldCode`：全局稳定字段代码
- `key`：当前对象内的兼容键
- `label`：界面显示名称
- `definition`：业务定义
- `dataType`：标准数据类型
- `nineElement`：所属美和9要素主维度
- `required`：是否必填
- `source`：数据来源方式
- `ownerRole`：业务责任人/责任角色
- `captureTiming`：字段在何时产生或确认
- `automation`：人工、AI辅助、自动、派生或混合
- `calculation`：确定性计算规则（如有）
- `validation`：校验规则
- `routes.knowledge`：知识说明路由
- `routes.rule`：规则路由
- `routes.help`：操作帮助路由
- `permission`：读取、写入与敏感级别
- `history`：历史记录策略
- `event`：字段变化事件
- `importAliases`：导入时允许的旧名称/业务名称
- `storageKey`：与既有本地/历史存储的兼容键
- `ui`：表单与显示元数据
- `db`：未来数据库类型与索引建议

## 3. 美和9要素映射

固定顺序始终为：

`目标｜人｜物｜事｜平台｜时间｜钱｜信息｜结果`

每个字段必须有一个**主归属维度**。字段可以在分析中与多个维度关联，但数据库与字段标准先确定一个主语义，避免含义漂移。

特别强调：

- 时间类字段必须说明“什么时间”，不能只叫“时间”。
- 钱类字段必须说明金额含义、币种/单位、来源与发生时点。
- 结果类字段要区分过程状态和最终经营结果。

## 4. 标准字段类型

当前基础类型包括：

`text / long_text / number / integer / money / percent / boolean / date / datetime / duration / url / email / phone / enum / multi_enum / status / person_ref / object_ref / file_ref / image_ref / json`

页面表单、AI工具参数和数据库字段应优先从该类型表映射，不再由每个页面自行判断。

## 5. 数据来源与自动化

字段来源标准：

`manual / system / inherited / api / import / ai / calculated / mixed`

自动化标准：

`manual / assisted / automatic / derived / mixed`

原则：系统已经知道、能够继承、能够计算或能够从API取得的数据，不要求员工重复填写。

## 6. 知识、规则、帮助分开

字段可以同时关联三个不同路由：

- **知识**：这个字段是什么、为什么存在
- **规则**：什么条件下如何判断/计算
- **帮助**：当前用户应该如何填写或处理

未建立正式内容时，路由状态为 `pending`，不生成虚假链接。知识之家内容成熟后只更新路由映射，不复制正文。

## 7. 权限原则

美和内部继续执行：**默认共享，敏感例外。**

普通字段默认：

- 读取：`internal_open`
- 写入：`responsible_or_admin`
- 敏感级别：`normal`

以后工资、银行、身份证件、密码、特殊合同等真正敏感字段再做字段级关闭。读取权限与写入权限分离。

## 8. 标准系统审计字段

每类正式对象统一预留：

- `id`
- `createdAt`
- `updatedAt`
- `createdBy`
- `updatedBy`
- `recordVersion`
- `sourceSystem`
- `archivedAt`

当前本地预演对象已开始补齐 `createdBy / updatedBy / recordVersion / sourceSystem`，为后端与审计做准备。

## 9. 字段与数据库的关系

字段标准是业务语义层，不等于数据库DDL。

后续数据库阶段应以：

`标准对象 → 标准字段 → 对象关系 → 事件/工作证据 → 数据库Schema`

进行实现。页面布局变化不应导致核心数据库字段随意变化。

## 10. 当前V1.0已覆盖

当前字段注册中心已覆盖：

- 客户之家
- 店铺之家
- 应用之家
- 支出之家
- 收入之家
- 现金支出
- 工作之家
- 分析之家
- 人才之家
- 分类之家
- 商品之家
- AI之家
- 共享之家
- 美和之家 / 知识之家统一内容对象
- 选品商品机会与当前批量导入/详情页关键字段

具体业务字段仍可在真实业务验证中增加，但新增字段必须先进入字段注册中心，不得重新散落到页面代码。

## 11. 变更原则

字段状态沿用：

`讨论中 → 验证中 → 正式锁定 → 废止`

正式锁定后的 `fieldCode` 如确需修改，必须记录：

`原fieldCode → 新fieldCode → 原因 → 数据迁移方式 → 影响范围 → 生效版本`

不得直接重命名导致历史数据失联。
