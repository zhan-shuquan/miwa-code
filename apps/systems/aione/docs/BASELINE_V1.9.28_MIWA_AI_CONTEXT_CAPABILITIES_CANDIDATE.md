# AIONE V1.9.28｜美和AI上下文分析、快捷能力与精准检索｜候选基线

状态：验证中  
日期：2026-08-26

## 本版目标

在V1.9.27已经真实跑通“美和AI找得到集团资料、AIONE能够安全交付Google Shared Drive原件”的基础上，继续解决三个真实使用问题：

1. 明确找某一份资料时，只返回唯一最佳结果，不再把整个资料库堆给用户；
2. 正常业务讨论不被“资料检索”劫持，而是读取当前AIONE页面的正式上下文后交给真实模型分析；
3. 把高频工作沉淀成结构化“快捷能力”，并保留当前浏览器中的AI会话连续性，让员工以“点一个能力 + 说一句话”的方式工作。

## 一、资料检索精准化

企业资料检索继续坚持确定性优先，不让模型猜版本、状态、Drive File ID或正式来源。

### 查询分流

- `给我 / 找一下 / 打开 / 下载 + 明确资料对象` → `single`，只返回唯一最佳结果；
- `有哪些 / 全部 / 列出 / 所有` → `list`，返回完整或规则允许的列表；
- `关于XX有什么资料 / 相关资料` → `related`，返回Top相关结果，默认不超过5项；
- 正常业务问题，例如“经营架构有什么可以优化？” → 不进入企业资料检索，继续走美和AI分析。

### “最新”规则

“最新 / 当前 / 正式”首先依据AIONE Registry中的`is_current / version / status`等结构化字段判断；不得由大模型凭文件名或时间猜测。

## 二、当前页面真实上下文分析

美和AI在美和之家讨论集团内容时，应读取当前页面已经存在的正式/验证中内容，而不是只根据页面标题生成通用管理建议。

### 经营架构页首批结构化上下文

- 433：四化 + 三基石 + 三属性；
- 四化：工作一体化、管理标准化、业务流程化、执行自动化；
- 三基石：美和灵魂、美和准则、美和传承；
- 三属性：普适、开放、共享；
- 经营主线：经营目标 → 业务流程 → 业务对象 → 状态与数据 → 规则与责任 → AI与自动化 → 人类负责人 → 结果指标 → 管理决策 → 持续优化；
- 闭环层级：操作闭环 → 业务闭环 → 经营闭环；
- 执行体系：指挥军、作战军、建设军、保障军；
- 四条执行原则与十步经营闭环；
- 人与AI责任原则：能规则化的规则化，能自动化的自动化，需要判断的交给AI，需要负责的留给人。

当用户询问“经营架构还有什么可以优化？”等问题时，真实模型应基于这些现有内容检查：闭环完整性、复杂度、可函数化规则、Skill条件、Connector/Agent/Computer Use机会、人类责任、真实验证指标等，只主动提出有价值的缺口。

## 三、快捷能力不是固定FAQ

新增结构化`AI快捷意图 / 常用能力`层。它不是保存几句固定问题，而是给自然语言建立稳定的业务意图入口。

首批包括：

- 全局：找资料、找人才、总结当前页、检查异常、下一步建议；
- 美和之家：找集团资料、找最新版、分析当前内容、检查结构缺口、下一步建议；
- 经营架构页：分析经营架构、检查闭环缺口、识别AI机会、形成优化清单。

快捷能力根据当前上下文动态展示；使用频率保存在当前浏览器本地，用于排序。员工无需理解背后具体是规则、API、Skill、Agent还是模型。

## 四、AI会话连续性边界

V1.9.28增加当前浏览器的AI会话历史恢复：刷新或重新打开AI层后，近期消息和资料卡可以恢复。

必须严格区分：

- 聊天历史：当前浏览器的交互连续性；
- 企业知识：经过状态、版本、来源管理的正式AIONE内容；
- 快捷能力：结构化业务意图配置。

本版聊天历史使用`localStorage`，不是集团正式知识库，也不是跨设备/跨成员永久会话。恢复历史资料卡时禁止自动重复下载文件。

## 五、真实模型生产启用

AIONE代码层继续保留Provider中立架构。生产真实分析通过：

`AIONE_AI_MODE=live` + `AIONE_AI_PROVIDER=openai`

第一阶段模型为`gpt-5.6-sol`。

### 安全边界

- OpenAI API Key不得写入仓库、页面、Cloud Shell配置文件或聊天；
- 正式生产Key只进入Google Secret Manager；
- Cloud Run Runtime Service Account仅获得Secret读取权限；
- `RUN_E_ENABLE_LIVE_MIWAAI.sh`负责检测已有Secret；没有时仅在Cloud Shell交互式隐藏输入一次；
- `RUN_D_DRIVE_SECURE_DOWNLOAD.sh`继续可用于Preview/基础设施验证，不强制真实模型作为文件闭环前提。
