# AIONE V1.1.0｜二级业务母版与系统参数大升级

**状态：** 共享内测候选 / 结构阶段性锁定  
**日期：** 2026-08-22  
**正式代码基线：** V1.0.28 Global Shell Single Source  
**原则：** 不在实验版本上叠补丁；以唯一 Global Shell 为根，把可复用结构抽成一份母版，业务页面只配置真实差异。

## 一、这次升级解决的问题

AIONE 后续会出现大量工作台、之家、业务对象页和详情页。如果每增加一种业务就重新设计页面、重新写列表、卡片、流程、指标、按钮和AI入口，单人长期维护不可持续。

V1.1.0 正式建立以下继承关系：

`Global Shell → 美和二级业务页面母版 → 通用组件 → 业务配置/真实数据`

以后新增业务页面优先回答“流程、对象、字段、规则和特殊能力是什么”，而不是重新回答“页面怎么画”。

## 二、一级母版：Global Shell

Global Shell 继续保持唯一源码：

- Header
- Sidebar
- Main
- Aside
- Footer

任何业务页面不得再内嵌第二套 Header / Sidebar / Aside / Footer。

### Header V1.1

第一层集团级入口：

`今日工作｜美和日历｜分析中心｜分类之家｜商品之家｜客户之家｜AI之家 │ 收入之家｜支出之家 │ 共享之家`

收入之家与支出之家作为集团经营事实入口相邻显示，并使用分割符与 AI之家、共享之家分组。

第二层统一为：

- `店铺之家 ›`：店铺统一管理与全部店铺入口；幸せ屋、PrimeLife、永井GD等保留为快速打开。
- `应用之家 ›`：应用统一管理与全部应用入口；Robot-in、佐川、黑猫、福山、GPT、WPS等保留为快速打开。

旧“跨境店铺 + 更多店铺”“工具 + 更多工具”的双入口结构退出当前运行 Header。

## 三、美和二级业务页面母版

唯一母版文件：`pages/business-home/template.html`

固定结构：

1. **业务头部**：图标 + 业务名称 + 简短说明 + 动作槽
2. **业务类型**：优先显示重点类型，更多类型横向滑动
3. **业务流程**：只引用该业务当前确认的流程配置
4. **业务指标**：统一结构，指标内容按业务配置
5. **业务对象管理**：搜索 / 筛选 / 导入 / 导出 / 卡片 / 列表
6. **辅助机动区**：只放该业务真正需要的特殊能力；无价值时隐藏
7. **美和9要素**：统一共享组件

### 业务头部动作规则

两个通用动作职责：

- `业务概览`
- `＋ 新建业务对象`

按钮文字由业务对象自动变化，例如：

- 选品：选品概览 / ＋ 新建商品机会
- 客户：客户概览 / ＋ 新建客户
- 店铺：店铺概览 / ＋ 新建店铺
- 应用：应用概览 / ＋ 新建应用
- 支出：支出概览 / ＋ 新建支出
- 收入：收入概览 / ＋ 新建收入记录

其他按钮按真实业务需要增减，不机械复制。

### 业务类型规则

默认重点类型数由系统参数 `business.priorityTypeCount` 控制，当前建议值为 3。

- 一屏优先显示最重要的3类
- 类型更多时横向滚动
- 类型顺序由统一分类字典决定
- 不因类型增多无限拉长页面

### 业务对象工具栏

统一保留：

`搜索｜筛选｜导入｜导出｜卡片｜列表`

卡片和列表必须共用同一份业务对象数据，不维护第二套记录。

## 四、美和9要素

“业务关键9要素”正式统一命名为：**美和9要素**。

唯一共享定义：

`目标｜人｜物｜事｜平台｜时间｜钱｜信息｜结果`

它是美和方法论在系统中的业务完整性检查框架，不是每个页面自己解释的一套字段。

其中“钱”必须明确回答：

- 有金额
- 待确认
- 不涉及

不得因为页面或流程设计遗漏而让经营事实中的金额消失。

## 五、当前共用母版的业务页面

以下 6 个页面路由已经共用同一个 HTML/JS/CSS 母版，业务差异集中在 `js/config/business-page-definitions.js`：

- 客户之家
- 店铺之家
- 应用之家
- 收入之家
- 支出之家
- 现金支出

### 客户之家

已锁定客户管理流程：

`发现客户 → 建立客户资料 → 客户分类 → 建立联系 → 形成商机 → 商谈/报价 → 成交/未成交 → 交易履约 → 持续维护 → 复购/沉睡/流失`

支持统一对象管理，并预置：

- A4标准客户档案打印 / 保存PDF
- 面单地址资料CSV导出

客户真实字段和大客户管理继续在真实业务使用中逐步验证。

### 店铺之家

管理对象包括：

- 店铺档案
- 负责人
- 账号状态
- 平台连接
- 经营状态
- 快捷入口

店铺管理流程仍为“验证中”，不冒充正式锁定标准。

### 应用之家

统一管理：

- 软件 / 系统 / 平台 / 数字工具
- 用途
- 负责人
- 账号 / 权限
- API / Connector连接状态
- 费用
- 关联业务
- 外部打开入口

应用管理流程仍为“验证中”。

### 支出之家

定位为美和集团所有可统计支出的统一总入口。

当前已建立统一对象、分类、页面和参数基础。真实业务自动归集仍需要采购、物流、工资、订阅、银行/卡等数据源逐项接入后才能正式验证，不在本版本虚构自动归集结果。

### 现金支出

支出之家的专用子页面，支持：

- Money软件导出数据
- Excel / CSV批量导入
- 少量人工补录

原则：已有数据不重新录入。

### 收入之家

已建立统一对象和页面骨架。各事业真实收入流程尚未完整验证，因此具体收入流程保持“验证中”，等待订单、批发、物流、留学等真实数据源接入。

## 六、AI存在机制

AI不单独制造另一套业务系统。

### 全局

- Header：AI之家
- Aside：`AI秘书｜当前业务辅助`

### 页面级

页面通过 `aione:page-ai-context` 把当前业务上下文送到唯一 Aside。没有高价值内容时保持轻量。

### 业务动作

在真正有价值的动作中使用AI，例如：自动分类、自动填充、异常分析、摘要和下一步建议。

自然语言“你告诉GPT/AI秘书 → AI整理 → 直接写入AIONE”的正式写入能力尚未接入真实后端/Connector，本版本只建立页面和标准事件接口。

## 七、新建业务对象 → 标准事件 → 通知

统一二级母版中的人工新建是长期兜底入口。

新建对象保存成功后：

1. 写入统一对象存储层（当前为内测 LocalStorage）
2. 触发 `aione:business-object-created`
3. 按系统参数决定是否生成普通“业务通知”
4. 通知中心统一展示

重要通知和普通业务通知严格分级：只有 `level=important` 的未读通知进入 Header“重要通知”槽位。

选品、测样等既有复杂工作台仍保护原业务逻辑；后续应在各自真实“保存成功”节点接入同一标准事件，而不是为了统一而提前破坏既有流程。

## 八、系统参数中心

系统参数升级为 AIONE 全局控制中心，当前包含 11 个参数域：

1. 系统基础
2. 组织权限
3. 分类字典
4. 业务规则
5. 金额与价格
6. 收入与支出
7. 店铺与应用
8. 导入与导出
9. 通知与任务
10. AI与自动化
11. 版本与审计

### 参数继承方向

当前共享内测主要使用“集团默认”。长期预设：

`集团默认 → 公司 → 事业 → 店铺/工作台 → 特殊对象`

下层只覆盖真正有差异的参数。

### 当前已经真实接入页面行为的参数

包括：

- 重点业务类型显示数量
- 业务概览 / 新建入口
- 美和9要素显示
- 允许新建 / 导入 / 导出
- CSV / XLSX导入开关
- 重复数据检查
- 新建对象自动通知
- 页面级AI秘书
- 参数变更原因与版本记录
- 既有选品成本、价格、物流参数

### 当前属于“接口/规则预留”的参数

以下项目已经形成统一参数位置，但真实自动执行需要后续数据源或后端接入：

- 收入自动归集
- 支出自动归集
- 店铺 / 应用链接定时检查
- 账号完整性自动巡检
- 完整角色权限与服务端数据范围控制

内测前台权限只能控制当前页面动作，不能替代正式后端权限校验。

## 九、兼容保护

为了不破坏已验证的选品成本与定价：

- 继续使用原 LocalStorage Key：`miwa-aione:restored-preview:v0.4:pricing-profiles`
- 保留旧 `common / shop / delivery / pricing` 参数结构
- 同时广播旧 `aione:global-pricing-updated` 和新 `aione:global-settings-updated`

V1.1.0 是架构升级，不重写已经验证的选品核心计算逻辑。

## 十、已删除/停止使用的重复实现

店铺之家已迁移到统一业务母版，因此旧独立 Store Home 的 HTML / JS / CSS 不再保留在当前运行工程中。

历史版本文档可以保留旧术语用于追溯，但当前运行代码不得重新引用旧“更多店铺/更多工具”结构或第二套业务母版。

## 十一、当前边界

本版本完成的是“可长期复用的基础结构”，不是宣称所有业务已经自动化：

- 真实多人共享仍需数据库/API接入
- AI秘书自然语言写入仍需正式Connector/后端
- 收入/支出跨工作台自动归集仍需真实Money Event数据源
- 店铺/应用自动巡检仍需对应API或定时任务
- 角色/数据范围安全必须由后端最终强制执行

这些能力以后应该接到同一母版、对象、参数与事件层上，而不是另做新页面体系。
