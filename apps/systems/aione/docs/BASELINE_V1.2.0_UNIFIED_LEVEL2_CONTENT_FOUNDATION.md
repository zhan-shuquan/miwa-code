# AIONE V1.2.0｜统一二级页面与内容体系基础架构

状态：**共享内测候选 / 基础架构阶段性锁定**  
日期：2026-08-22  
升级母体：**V1.1.0 Level-2 Template System Upgrade**

## 1. 本版本定位

V1.2.0 不是新增若干独立页面，而是把 V1.1.0 之后确认的页面生产方法进一步收敛为可长期复用的基础架构：

> **一个 Global Shell + 一个统一二级页面基座 + 美和业务母版 + 美和内容母版 + 少量高复用组件 + 真实业务/内容配置。**

本版本的目的，是让后续新增页面优先变成“选择母版并配置对象、流程、字段和规则”，而不是从白纸重新设计页面。

## 2. Global Shell 继续唯一化

全系统继续只保留一套：

- Header
- Sidebar
- Main
- Aside
- Footer

任何业务页、内容页、通知详情页不得再内嵌第二套 Global Shell。

## 3. Header 信息架构升级

### 3.1 公司识别

点击 AIONE 公司识别区进入 **美和之家**。

### 3.2 第一层集团级入口

当前核心入口包括：

- 今日工作
- 美和日历
- 分析中心
- 分类之家
- 商品之家
- 客户之家
- 人才之家
- AI之家
- 收入之家
- 支出之家
- 知识之家
- 共享之家

其中收入之家 / 支出之家作为同一经营资金事实组显示；知识之家 / 共享之家保持独立职责。

### 3.3 第二层高频入口

- **店铺之家 ›**：负责店铺管理；具体店铺继续作为快捷入口。
- **应用之家 ›**：负责应用管理；具体应用继续作为快捷入口。
- Google Drive 正式纳入应用资产，并保留 Header 高频直接入口。

原则：

> **“之家”负责管理，“具体对象”负责快速打开。**

## 4. 正式定义“之家”

“之家”不是命名风格，而是对一类集团核心对象、能力或资源进行长期统一管理的入口。

当前职责：

- **美和之家**：管理公司本身。
- **知识之家**：管理知识。
- **共享之家**：管理能力和客观存在的共享资源。
- **分类之家**：管理分类。
- **商品之家**：管理商品。
- **客户之家**：管理客户。
- **人才之家**：管理内部人才与人事对象。
- **店铺之家**：管理店铺。
- **应用之家**：管理应用、软件、系统、平台和数字工具。
- **AI之家**：管理 AI 能力。
- **收入之家**：管理收入事实。
- **支出之家**：管理支出事实。

禁止为了名称统一继续产生“标准之家 / 制度之家 / SOP之家”等低必要性之家。方法论、标准、制度、SOP 等文字知识统一归 **知识之家**。

## 5. 美和业务母版

唯一业务母版：

`pages/business-home/template.html`  
`js/pages/business-page-template.js`  
`css/pages/business-page-template.css`

标准结构：

1. 业务头部
2. 对象类型横向轨道
3. 管理流程 / 业务流程
4. 核心指标横向轨道
5. 对象管理
6. 辅助机动区横向轨道
7. 美和9要素

### 5.1 业务头部

统一动作职责：

- 概览
- ＋ 新建当前业务对象

按钮文字按对象语义变化，例如“客户概览 / 新建客户”“应用概览 / 新建应用”。其他任务、报告、审批等动作按真实业务增加，不机械复制。

### 5.2 类型模块

底层组件统一，前台名称按对象变化：

- 客户类型
- 商品类型
- 店铺类型
- 应用类型
- 人才类型
- 收入类型
- 支出类型
- 选品类型

默认一屏优先显示 3 个重点类型，更多内容横向滑动，不增加页面纵向高度。

### 5.3 流程语义

“之家”显示当前对象如何被长期管理：

- 客户之家 → 客户管理流程
- 商品之家 → 商品管理流程
- 店铺之家 → 店铺管理流程
- 应用之家 → 应用管理流程
- 支出之家 → 支出管理流程

工作台显示真实业务执行流程：

- 选品工作台 → 选品业务流程
- 测样工作台 → 测样业务流程

流程图只保留一套共享组件。流程节点由业务配置决定，页面不得重新绘制第二套流程。

### 5.4 核心指标

统一标题为 **核心指标**。

- 只展示高频、重要指标。
- 数字优先、大且醒目。
- 一屏最多 6 项。
- 超过 6 项继续横向滑动。
- 不因新增指标改变页面基础高度。

### 5.5 对象管理

统一工具栏：

`搜索｜筛选｜导入｜导出｜视图切换`

业务管理默认使用“卡片 / 列表”。卡片和列表必须来自同一对象数据源。

卡片与列表的标准字段常显；低频详细信息进入详情页。**不得用“展开更多”隐藏卡片/列表的标准业务字段。**

### 5.6 区块折叠

`Disclosure / Accordion` 只用于次级信息，例如：

- 参数
- 依据
- 历史
- 规则
- 说明
- 附件
- 审计信息

它与卡片/列表字段显示是不同职责。

### 5.7 辅助机动区

统一为：

> **单行 + 自适应卡片宽度 + 横向溢出**

不锁死 3 列、4 列或 5 列。没有高价值辅助内容时可以整区隐藏。

## 6. 美和9要素

正式名称统一为：

> **美和9要素**

内容：

`目标｜人｜物｜事｜平台｜时间｜钱｜信息｜结果`

定位：

> **美和方法论贯穿 AIONE 及未来美和系统的业务流程和各种管理的统一完整性检查框架。**

其中“钱”必须明确回答：

- 有金额
- 暂未确定
- 不涉及

不得出现“没有考虑”。

## 7. 收入之家 / 支出之家

收入、支出作为业务事实的一部分，不要求二次重复录入。

目标链路：

`业务发生 → 美和9要素识别钱 → Money Fact → 收入之家 / 支出之家 → AI财务参谋 → 分析中心`

### 7.1 支出之家

所有可统计支出统一归集，包括采购、物流、人员、房租、水电、宽带、应用订阅、广告、差旅、办公用品、现金等。

### 7.2 现金支出

现金支出作为支出之家下的专用业务入口，允许：

- Excel / CSV 导入
- Money 等软件导出文件导入
- 其他已有支出数据导入
- 少量手工补录

原则：**已有数据不重新录入。**

## 8. 美和内容母版

新增唯一内容母版：

`pages/content-home/template.html`  
`js/pages/content-page-template.js`  
`css/pages/content-page-template.css`

首批入口：

- 美和之家
- 知识之家

标准能力：

- 内容头部
- 内容分类横向轨道
- 核心指标
- 搜索 / 筛选 / 导入 / 导出 / 卡片 / 列表
- 相关内容横向轨道
- 内部路由 / 外部来源关联
- AI秘书内容辅助
- 状态、版本、负责人、更新时间

本版本只锁定二级内容管理入口。完整三级内容详情 / 编辑器 / 出版流程留到后续讨论，不在本版本扩大范围。

## 9. 美和之家

美和之家负责管理“美和集团本身”，包括：

- 企业介绍
- 美和精神
- 美和准则
- 美和传承
- 发展历程
- 集团事业
- 组织与品牌
- 企业资料

重要知识可以在美和之家引用，但正式知识源仍然归知识之家，不复制第二份。

## 10. 知识之家

知识之家是所有知识相关文字内容的新建、管理、维护、检索和版本统一入口。

知识类型包括：

- 方法论
- 标准
- 制度
- SOP
- 业务知识
- 培训资料
- 案例 / 研究
- 系统 / AI知识

知识保持一个正式 Content ID，未来可被：

- 美和之家
- AI秘书
- 帮助中心
- 培训
- 官网
- PDF
- 电子书

等多个渠道调用。后续出版时应基于正式知识生成版本快照，避免修改知识源后影响已出版版本。

## 11. 共享之家边界

共享之家管理 **能力和客观存在的共享资源**，包括：

- 文件资产
- 账号资产
- 美和图标 / Logo
- 美和图片
- 美和视频
- 共用素材
- 共用模板
- 共享工具
- 公共资源
- 可复用能力
- 代码资产 / GitHub入口

文件与资料如继续以 Google Drive 为正式本体，AIONE 管理目录、关系和打开入口，不要求复制文件。

判断原则：**看内容本质，不看文件格式。**

例如制度 PDF 本质是知识，归知识之家；Logo源文件本质是资产，归共享之家。

## 12. 人才之家与 PPC “人”

人才之家管理内部人才、人事和组织关系对象。

- 客户之家：对外客户关系对象。
- 人才之家：对内人才与组织关系对象。
- 外部 People关系系统：外部 People 的发现、信任建立、人才吸引和关系连接。

三者在 PPC “人”的上层概念中的关系，由知识之家中的正式方法论内容解释，不把方法论说明复制到业务对象中。

## 13. AI存在机制

AI继续采用三层机制：

1. 全局：AI之家 / AI私人秘书。
2. 页面：Global Aside 的“AI秘书｜当前上下文辅助”。
3. 动作：只在真实有价值的场景中提供 AI读取、填充、分类、检查、总结、建议和生成。

人工“新建”始终保留。未来 AI秘书调用同一对象创建机制，而不是创建第二套 AI 数据。

## 14. 重要通知 P0 升级

通知中心作为共享内测马上使用的 P0 能力纳入本版本。

统一二级页面结构：

- 通知头部
- 通知类型横向轨道
- 通知管理流程
- 核心指标
- 通知记录（搜索 / 筛选 / 导入 / 导出 / 卡片 / 列表）
- 辅助机动区
- 美和9要素

新增通知详情页，支持：

- 正文唯一正式内容
- 发布主体
- 发布对象
- 发布时间 / 截止或会议时间
- 阅读状态
- “我已知悉”确认
- AI秘书上下文辅助

预期长期链路：

`GPT布置 → AI秘书整理 → 人确认关键发布 → AIONE通知 → 阅读/确认 → AI汇总`

本版本保留人工新建通知作为内测兜底。

参数中心继续统一维护：

1. 系统基础
2. 组织与权限
3. 分类与字典
4. 业务规则
5. 金额与价格
6. 收入与支出
7. 店铺与应用
8. 导入与导出

11. 版本与审计

“重点类型一屏3项”属于当前 UI标准，不再作为业务人员随意调节的普通参数。

## 16. 特殊页面

今日工作、美和日历、分析中心仍继承统一 Level-2 页面语言（头部、核心指标、按钮、Aside等），但 Main 保留符合对象真实使用习惯的视图：

- 今日工作：任务 / 建议与创新
- 美和日历：日历 / 日程
- 分析中心：分析图表 / 数据视图

不为了表面统一破坏真实操作体验。

## 17. 当前技术边界

当前二级业务对象、内容对象、通知对象仍有一部分使用浏览器 LocalStorage 进行内测预演。

以下能力不冒充已完成：

- Cloud SQL/API 的所有新对象正式持久化
- Google Drive/GitHub文件内容自动同步
- GPT/AI秘书自然语言直接写入AIONE正式数据库
- 银行 / Money / 物流 / SaaS支出的自动对账
- 完整三级内容详情编辑器与电子书出版

这些能力将在数据库/API和真实外部数据源接入后继续实施。

## 18. 后续开发纪律

新增页面前按顺序判断：

1. 是否能直接继承 Global Shell？
2. 是否属于美和业务母版或美和内容母版？
3. 是否已有横向轨道、流程、核心指标、对象工具栏、卡片、列表、Disclosure、辅助机动区、美和9要素等组件？
4. 是否只需要新增配置、字段、流程和规则？
5. 只有真实需求证明现有母版无法合理承载时，才讨论新增母版或页面结构。

核心目标：

> **页面越多，共享代码越多；复杂逻辑留给系统，简单操作留给人。**
