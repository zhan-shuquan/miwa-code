# V1.9.36｜工作之家统一 Work Item Browser 体验收口｜Candidate

基线：用户确认的 V1.9.35 WORK HOME UNIFIED BROWSER + CONTRIBUTIONS CANDIDATE。

## 本轮目标

今天最后一次体验收口，不继续扩页面数量。重点把所有工作事项入口统一到同一套 Work Item Browser：

- 搜索
- 高频筛选
- 时间筛选
- 更多筛选
- 重置
- 排序
- 卡片 / 列表
- 2列 / 3列 / 4列
- 刷新
- 点赞 / 关注

入口只改变 Query，不改变 Work Item 事实、处理权限与执行闭环。

## 锁定体验

1. 工作卡不再支持6列；统一为2/3/4列，默认3列，并按浏览器容器宽度自动降列，避免Sidebar/Aside存在时卡片被挤成窄条。
2. 刷新与排序、卡片/列表、列数归入同一右侧工具组，不允许刷新按钮单独掉到下一行。
3. 全部工作一级增加“时间”：全部时间 / 今日 / 本周 / 本月 / 本年 / 自定义。
4. 更多筛选承载团队、项目、时间依据、金额、最低金额等低频条件；有条件生效时显示数量；“重置”恢复当前入口默认Query。
5. 工作记录中的“工作明细”直接复用统一 Work Item Browser 的搜索、筛选、排序、卡片/列表和2/3/4列；只把时间口径换成本周/本月/本年工作事实。
6. 涉及资金的工作读取 money_events，在卡片/列表中条件显示财务摘要；更多筛选可查“涉及金额/无金额/最低金额”。
7. 已有 work_sessions 作为真实操作时间事实源；工作卡/列表仅在存在真实记录时显示“已记录X分钟/小时”，不把页面停留时间伪装成工作时间。
8. 关注继续复用 work_item_participants(observer)。点赞新增 object_reactions 事实表；点赞和关注完全独立。
9. “我的关注”中的“点赞记录”是二级查询，不新增Sidebar“我的点赞”。
10. 点赞/关注均要求Backend真实写入；刷新页面后状态必须保持。

## 经营边界

- 钱是经营影响证据，不等于金额越大优先级必然越高。
- 时间是效率和产能证据，不等于在线时间或页面停留时间。
- 点赞是认可信号，关注是动态订阅，浏览是阅读事实。
- 工作记录是事实层，绩效评价仍由结果、质量、责任、协作、改进贡献和管理判断形成。
