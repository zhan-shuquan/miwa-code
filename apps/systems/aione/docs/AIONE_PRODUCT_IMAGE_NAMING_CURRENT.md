# AIONE 商品图片命名 CURRENT V1.1（简化版）

**状态：正式规则（2026-10-12 确认）**。本文件是本地图片新建/导入命名的唯一 CURRENT 事实源；旧版复杂分类命名说明不再作为员工操作标准。

## 一、员工只需要记住两套规则

| 用途 | 文件名 | 说明 |
| --- | --- | --- |
| 商品首图 | `zjl238_01.png` | 第 1 张商品图片，作为主图候选 |
| 后续展示与详情图 | `zjl238_02.png`, `zjl238_03.png`, ... | 按编号排序；图片数量由实际素材决定 |
| SKU/颜色/款式规格图 | `zjl238_c01.png`, `zjl238_c02.png`, ... | 统称 SKU 图；不再另建颜色图命名 |

统一命名结构：`{本地商品货号}_{序号或 c序号}.{扩展名}`。支持 JPG、JPEG、PNG、WebP；扩展名需与图片实际编码一致。不得设置固定 9 张或 15 张数量限制。

**通用图片 `gift.*` 暂缓建设。** 尚未建立共享图片库和关联机制前，扫描程序忽略这类图片，不自动归属任何单品。

## 二、历史兼容与废止说明

- `_ma`（白底）、`_dNN`（独立细节）、`_rNN`（实拍）和 `_skuNN`（旧 SKU 图）的**新建命名规则已废止**。不要求员工按这些旧格式保存新文件。
- 现有本地图片、Cloud Storage 对象、R-Cabinet 文件和已有商品引用**不得自动重命名、删除或覆盖**；旧文件保留只读兼容，并由独立迁移流程处理。
- 上传图片到 AIONE ≠ 发布到乐天。ItemAPI/R-Cabinet 发布需要独立预检和人工确认。

## 三、平台级统一原则

- 文件名中的 `zjl238` 用于找商品；进入 AIONE 后通过**不可变商品 ID** 关联到唯一 ProductAsset 体系。系统内部规范化名称可独立于本地文件名，不要求员工修改原图。
- `_01` 是商品首图候选；`_02` 起为后续产品展示、详情图，不再要求员工额外分类。
- `_cNN` 只用于临时扫描/展示顺序，不能被视作永久 SKU ID。**SKU 图片绑定必须以 AIONE 内部 SKU 身份及真实颜色/款式等规格核对为准**。
- 云端图片二进制存于既有 Google Cloud Storage，商品图片元数据与关联存于既有 Cloud SQL 的 ProductAsset；不新建第二套图片数据库。
- 本地预检通过后可进入分批受控上传；首次试运行必须逐张确认 SHA-256、图片顺序、用途及商品 ID；同内容重跑不可生成重复素材记录。
- Windows 不保存 Google Cloud 服务账号私钥；同步必须采用受控身份验证/授权，发布权限与图片同步权限分离。
- 将来 AIONE 自有 AI 出图能力成熟后可演进**内部**标准与用途分类；前台员工命名仍保持简单，历史文件不受影响。

## 四、已验证与待开发边界

- 已验证：Windows V1 本地只读扫描，`zjl238` 实际识别 12 张稳定图片（主图 1、后续展示图 9、SKU 图 2），0 项阻断；不会上传、删除或修改原图。
- 待开发/待验收：安全批量上传接口、Windows 自动监控/授权、GCS 文件核验、ProductAsset 关联、SKU 人工关联确认，以及乐天 R-Cabinet/ItemAPI 上架闭环。
- 历史资料中固定 9 张、固定 15 张及复杂 `_ma/_d/_r/_sku` 命名要求均不得重新作为新上架流程的 CURRENT 规则。
