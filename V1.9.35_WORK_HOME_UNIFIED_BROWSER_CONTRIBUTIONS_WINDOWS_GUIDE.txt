一、更新方式
1. 停止本地 AIONE / Live Server。若正在运行 AI Backend，可保留；本版本不修改Backend代码。
2. 解压本次 ZIP，打开其中 code 文件夹。
3. 将 code 文件夹内部内容合并/覆盖到 D:\miwa\code\ 。
4. 选择替换同名文件；不要先删除 D:\miwa\code，本次仍为增量覆盖。
5. 重新启动页面，并执行浏览器强制刷新，避免旧 Work Home 模块缓存。
6. GitHub Desktop 检查变更，人工验收通过后 Commit + Push origin。

二、本版不需要数据库迁移，也不新增Backend
- Work Item 继续是唯一工作事项事实源。
- 不新增第二套今日工作、事业工作、关注工作、等待工作或验收工作数据。
- 点赞Backend本版不新增；前端仅预留交互位置，不伪造点赞事实。
- 关注Backend本版不修改；若当前服务器关注接口尚未部署，关注仍可能提示Backend待接入，本版不把它作为发布阻塞项。
- “我的建议 / 我的创新”本版建立正式页面入口、组织归口与闭环说明；正式多用户投稿数据库/API后续开发，不伪造提交成功。

四、本版重点人工验收

1. Header默认路由
- 点击Header“工作之家”，应直接进入“今日工作”，不再先打开《美和工作手册》。
- 工作概览仍作为《美和工作手册》入口。

2. 统一工作事项一览
- 今日工作、全部工作、我的关注、事业工作、等待中、异常处理、待验收应保持同一工作卡/列表语言。
- 从不同入口看到同一Work Item时，详情、负责人、状态、处理入口必须一致。
- 全部工作应有明显“今日工作”快捷入口。

3. 全部工作筛选工具栏
- 应看到搜索、常用筛选、更多筛选、排序、卡片/列表、刷新。
- 更多筛选展开团队/项目等低频条件。
- 选中更多筛选后，“更多筛选”应显示生效数量。
- “重置”应恢复当前入口默认查询，不应误把事业入口等固定条件清空。
- 卡片模式支持3列/4列/6列密度切换（空间不足时响应式降级）。

4. 场景减法
- 我的关注、今日工作等页面不应机械复制全部工作的所有筛选按钮和KPI。
- 底层浏览能力统一，但前台只显示当前场景必要控件。

5. 事业工作
- Sidebar优先显示美和跨境、美和批发、美和留学、更多事业。
- 点击某事业后，应进入同一Work Item Browser并自动带入事业条件。
- 非事业成员如果有可见权限，仍可查看并从相同Work Item详情进入；权限由Work Item决定，不由入口决定。

6. 等待中 / 异常处理 / 待验收
- 等待中：正常外部等待或下次检查事项。
- 异常处理：阻塞/错误等需要恢复正常推进的工作。
- 待验收：执行已完成、等待结果/证据验收的工作。
- 三者均是Work Item Browser的高价值快捷入口，不另建数据源。

7. 我的建议 / 我的创新
- Work Home应出现两个个人入口。
- 页面应明确建议与创新的定义、集团归口、生命周期和转Work Item/Project路径。
- “提出建议 / 提出创新”目前不得显示假提交成功；应明确正式Backend待接入。

8. 美和之家集团归口
- 美和之家 -> 经营与战略 下应出现：经营架构、发展战略、发展规划、建议中心、创新中心。
- 建议中心说明：个人提出 -> 集团分诊/受理 -> 责任人 -> Work Item/Project -> 验证 -> 结果回写。
- 创新中心说明：创新不限于AI，需概念/真实业务验证，成熟成果再进入知识之家并回写人才贡献。

9. 工作记录
- 支持本周 / 本月 / 本年。
- 人员汇总支持卡片 / 列表；人员资料优先读取统一用户/人才主数据头像、姓名、岗位，缺失才回退首字头像。
- 人员卡展示负责、参与、闭环、主要事业、主要项目、主要流程等工作事实。
- 工作明细支持卡片 / 列表，并直接复用统一Work Item Browser展示语言，不再另造一套工作记录列表。

10. 《美和工作手册》
- 继续使用统一数字出版物母版。
- 应按最新Sidebar补齐：今日工作、全部工作、我的关注、我的建议/创新、事业工作、等待中、异常处理、待验收、工作记录等使用指南。
- 工作概览是场景数字手册；帮助中心未来聚合这些手册，不重复维护另一份说明。

11. 既有执行闭环回归
- Proposal -> Human Confirm -> Work Item不受影响。
- 开始执行、证据、提交完成、验收、美和AI复盘继续正常。
- Header提醒继续使用同一work_items事实，不新增重复统计。
